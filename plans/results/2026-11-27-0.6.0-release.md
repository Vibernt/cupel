# 0.6.0 release (2026-11-27)

npm package **0.6.0**, Python collector **0.4.1** (Windows fix only). node:test measures JSX and TypeScript that a project
loader runs and tests their faults through that loader; faults in `.ts` under a loader are no longer reported caught
when they were not; sources a runner cannot measure are listed apart in reports instead of dropped; TypeScript
declaration files are no longer counted as code. Registry uploads stay unapproved (L6). Details: `docs/node.md`.

## New: JSX and TypeScript that node:test runs through a loader

- **Measured.** A `.jsx`/`.tsx` file is measured when a test process loads it through the project's loader (tsx,
  a `module.register` or `module.registerHooks` hook, or a CommonJS `Module._extensions` handler) and the loader's
  output has an inline source map back to the unchanged file. Coverable lines come from the project's own
  `typescript`; per-test coverage is mapped back through the same mapper Vitest uses (K1, K2).
- **Not measured, with a reason saying which:** JSX no test loads, JSX that tests may run only in child processes
  with a loader of their own, JSX loaded without a usable source map, JSX when `typescript` cannot be resolved or
  cannot parse it. Lines are never guessed.
- **Fault testing (K6).** A fault is handed to the project's loader to transform, and carries one extra statement
  (no line moves) that proves the fault's code ran. A fault is scored only when every process whose coverage holds
  the file ran it; otherwise it is `error`, never caught or unnoticed. Setups that give `error`, not scores: tsx's
  CommonJS path, a loader that reads the file itself, a loader a `--require` preload registers that changes the
  text. `docs/node.md` has the full table.
- **Combining runners (K14).** Another runner's lines stand for a JSX file only when no node:test process could
  have run it; a file node:test runs but cannot map is refused when another runner measures it.

## Fixed

- **Faults in `.ts` under a loader reported caught when they were not.** With an async loader (tsx 4.21's
  `module.register`, say), Cupel's own hook replaced the loader's output with the raw file, so every fault in a
  `.ts` file failed to load and counted as caught, even one on a line no test reaches. Any fault planted while a
  loader is in play now goes through the loader and carries the run proof. In earlier releases.
- **Covered lines of loader-transformed `.ts`/`.js` read against the wrong text.** A source a loader compiles is
  now mapped back through its inline source map; one without a usable map is listed as not measured. Text identical
  to the file, or Node's own type stripping (lines kept), is measured as before. In earlier releases.
- **Node 22 module-hook bugs.** On Node releases with either of two module-hook bugs (probed at run time: seen on
  22.16.0 and 22.22.0, not on 22.23.1 or 26.7.0), fault testing with any loader or preload in play stops with an
  environment error instead of scoring: a hook-only failure could make surviving faults look caught or caught
  faults look unnoticed. These releases are below the supported minimum.
## Fixed

- **Sources a runner cannot measure** ([issue 9](https://github.com/Vibernt/cupel/issues/9)). Under node:test, a
  `.tsx` source was skipped as `Unterminated regex at offset N` (the shared lexer read the `/` of a closing tag as a
  regular expression), a `.jsx` source was dropped without a word, and neither the report nor the audit said that
  sources were left out. Node runs no JSX without a loader. Now:
  - node:test lists `.jsx` and `.tsx` sources it cannot measure (above) in the input with no coverable lines and
    the reason (SPEC K2, I3), and logs them once;
  - a source node:test or Vitest cannot read, and a Vitest source whose coverage cannot be mapped back through a
    source map, is listed the same way with its cause, instead of disappearing (it is still named in
    `.cupel/skipped.json`);
  - the report's suite totals carry `unmeasured`, the count of such sources, when there are any (SPEC R3), and the
    summary line reads `coverage 75% (3/4), 2 sources not measured, …`;
  - the audit's coverage section says how many sources were not measured beside its percentage and lists each with
    its reason, never as uncovered;
  - `collect-node` (strict) no longer fails on a project that holds JSX: a runner limit is not an incomplete
    inventory;
  - a source that could not be measured stays in the fault-result reuse basis, since tests may run it unseen
    (K15);
  - combining runners keeps the lines of the runner that measured a source only when the other runner cannot run
    it at all (JSX no node:test process loaded); when the other runner's tests may run it unseen (a Vitest source-map failure,
    an unreadable file), the combination is refused instead of reporting faults without those tests (K14). Before
    this release such a source was silently dropped by the runner that could not measure it;
  - a guard whose head cannot measure a source its base measured warns `source-unmeasured` (G4);
  - `cupel pseudo` skips sources that could not be measured, and `mutate --input` accepts a source that could
    not be read (it holds no faults); the experimental Node PR profile names JSX as the reason it refuses a `.tsx`
    instead of `Unterminated regex`;
  - reasons name a system error by its code (`EACCES`), never by a path on the machine.
- **Declaration files counted as uncovered code.** `.d.ts`, `.d.mts`, `.d.cts` and `.d.<ext>.ts` files hold only
  types, but node:test and Vitest counted their lines as coverable and never covered (one four-line `price.d.ts`
  took a project from 75% to 37.5%). They are no longer sources in any JavaScript runner (node:test, Vitest, Jest,
  the experimental Node PR profile).

## Not verified

- Linux and Windows, until the hosted CI completes a run.
- A Vitest run with a real source-map failure (the mapping-failure branch is exercised only by reading the code).
- The experimental Node PR profile still ignores `.jsx` files, as before.
- `@babel/register` and `@swc-node/register` (fixture hooks in their style only); source maps in separate `.map`
  files (not measured); Node 23.x, 24.x and 25.x; Node 22.23.3 (22.23.1 was run).
- A loader a `--require` preload registers that changes the file's text gives `error` for its faults: Cupel cannot
  register ahead of `--require`.
