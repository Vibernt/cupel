# 0.5.0 release (2026-11-25)

npm package **0.5.0**, Python collector **0.4.0**. Rust builds kept between runs and shared between CI
slices, likely catchers first in every runner, Go and Ruby fault testing brought up to the other runners, and
one shared build for Go. Registry uploads stay unapproved (L6). Plans: `plans/RUST-BUILD-REUSE.md`,
`plans/LANG-SPEED.md`, `plans/RELEASE-0.5.0.md`.

## What is new

- **Rust build sessions** (D24, `backend: "cupel"`): the build lives in a session in the per-user cache
  (`CUPEL_CACHE_DIR` or `--cache-dir`, else the platform cache folder; never inside the project), brought up to
  date before every use, locked against concurrent runs, restored after a crash, capped at 10 GB together
  (`sessionCapGB`) with least-recently-used eviction, and removed with `cupel clean --rust-sessions [--project]`.
  The unmutated passes and the switches-off verdict are reused only when nothing changed: project content, test
  environment, every executable of the build and the named tests. `session: false` keeps the old throwaway copy.
- **Rust whole-function variants** (D25, opt-in `bodyVariants`): operator faults that regroup an expression
  (`&&`↔`||`, `+`→`*`) join the shared build as one-line copies of their function body; refused when unsure.
  `CUPEL_RUST_VERIFY_SWITCHED=1` reruns every switched fault on its own build and refuses on any disagreement.
- **Rust in CI** (D26): `mutate --prepare --cache-dir DIR` sets up the whole plan once; a slice restoring that
  session at the same path skips the cold build and reuses the setup results, and still runs only its faults.
  `sessionEnvIgnore` names job variables no test reads; Cupel's own `CUPEL_*` variables never count. Stable
  fault numbering makes every slice render the same switched sources.
- **Likely catchers first, in every runner** (D27): the tests that caught a fault in the previous input run
  first, then tests written for the fault's own source file, then the existing input order. Rust, Go, Ruby,
  JavaScript/TypeScript and pytest. Order changes which tests are credited before the stop rule and can turn a
  timed-out fault into a caught one (both detected); never a detected fault into an unnoticed one.
- **Go fault testing** (D28): only the packages and tests that run the line (`-run`), stop after two catching
  packages (one at the first catch for guard), K15 reuse when the basis holds every test file Go compiles, and
  one switched build (whole-function variants through `-overlay`) with a switches-off check per package and
  individual builds as the fallback; `CUPEL_GO_VERIFY_SWITCHED=1`; `runners.go.mutants.schemata: false` turns it
  off. Go rows now carry `durationMs`.
- **Ruby fault testing**: stop after two catching tests (one at the first catch), likely catchers first; a
  reported failure now decides the status even when a later test errors or times out.
- **Documentation site** at https://vibernt.github.io/cupel/ (once GitHub Pages is enabled): built by a
  zero-dependency script (`node scripts/site/build.mjs`) from `docs/`, Fire-styled, with search, light and dark
  themes, a mobile layout and a link check (the build fails on any broken link or anchor); deployed by
  `.github/workflows/pages.yml`. The README is rewritten around real output.
- **Hosted CI** (`.github/workflows/ci.yml`): Ubuntu, macOS and Windows with Node 22.23.3 and 26.7.0, Go 1.27.1,
  Ruby 4.0.7 with Minitest 6.0.0, Python 3.14 with pytest 9.1.1, Rust 1.97.1 with LLVM tools, cargo-mutants
  27.1.0, Jest 30.2.0, Vitest 4.1.11 and 5.0.1 and Miniflare 5.0.0, with the Go, Ruby, Jest and package-smoke
  gates required. The restricted Rust backend's tests now skip off their exact Homebrew profile unless
  `CUPEL_REQUIRE_RESTRICTED_RUST=1`.
- **Output changes**: Go rows carry `durationMs`; a Ruby `timeout` row no longer lists the timed-out test in
  `killedBy` (a timeout credits no test, as in every other runner).
- **Rust details**: every named test must report a result (a filter that matches nothing is never a pass); no
  long retry when a timed-out run already reported a real failure; `mutate-rust: timings` and
  `CUPEL_RUST_TIMINGS`.

## Full suite

On the build machine (macOS, Apple silicon) with Go 1.27.1, Ruby 4.0.7, Python 3.14 and pytest 9.1.1, LLVM
tools, cargo-mutants 27.1.0, Miniflare and Node 26.7.0: 903 Node tests, 837 passed, 18 failed, 48 skipped; Python
and Ruby (39 runs) all passed. Compared with `main` under the same tools, no test fails that passes on `main`;
two that fail on `main` now pass or skip correctly (the npm package smoke, and the restricted Rust CLI test, now
skipped off its exact Homebrew profile). The 18 failures are the remaining missing-tool cases (Node 22.23.3 for
the experimental selective commands, the Vitest fixture packages, Jest/workerd environment pieces), which the
hosted CI installs.

## Not verified

- Linux and Windows.
- Real Go and Ruby repositories (fixtures only).
- The npm package smoke on this machine stops at its Rust step (pinned Homebrew Rust 1.97.1 is not installed),
  so its Go and Ruby steps did not run.
- Slices on a real CI system (`--prepare` is tested locally).
- Ruby result reuse stays off: the basis does not identify installed gems or Bundler/Gem path settings.
- One Go variant that fails to compile sends its package to individual builds (slower, never wrong).
- JavaScript and Python unmutated passes are not kept between runs.
