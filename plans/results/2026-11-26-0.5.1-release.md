# 0.5.1 release (2026-11-26)

npm package **0.5.1**; the Python collector stays **0.4.0**. A fix for runners that test the same sources, and the
hosted CI's setup. Registry uploads stay unapproved (L6).

## Fixed

- **Runners sharing a source** ([issue 7](https://github.com/Vibernt/cupel/issues/7)). With two JavaScript runners
  in one `cupel.json` (node:test and Vitest testing the same `src/`, say), each runner planted the same mutants and
  `report` stopped with `duplicate mutant id across runners` (exit 3). Now each mutant on a shared source runs
  against every runner's covering tests and the rows combine into one (SPEC K14): `killed` when any runner's tests
  caught it, with the union of `killedBy` and `killKinds`; otherwise `timeout`, then `error`, then `survived`, then
  `no-coverage`. A mutant that no runner caught, and that a runner holding the source and covering its line did not
  run (a sample or time budget left it out), has no complete answer: it is left out and `sampled` is true, and a
  targeted unit covering it is no longer reported complete. Survivor confirmation runs with every runner whose tests
  ran the mutant and combines the same way, keeping the row's measured time. Merging saved runner inputs
  (`merge-runners`) combines shared mutants the same way instead of refusing them. The combined row's reuse basis is
  computed over every runner's covering tests, as before.
- **Hosted CI setup.** The 0.5.0 run on `main` stopped before the tests: Miniflare `5.0.0` does not exist (now
  `5.20261101.0-beta`, the version the maintainer's Workers project uses, with its install scripts so `workerd`'s
  binary is fetched), and npm on Node 22 crashed installing named packages into a folder whose `package.json` had no
  name (each tool folder now gets a complete manifest and a plain install).
