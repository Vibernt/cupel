# 0.2.0 candidate (2026-11-23, branch `audit-rust-workerd`, local commits)

**Status: candidate, not released.** Pushing the branch, tagging and any
registry upload each need the owner's separate approval (L6). npm stays
`private: true`; Python keeps `Private :: Do Not Upload`.

## What is new

- **`cupel audit`** (SPEC 11b, U1-U7; CLI with Markdown output; MCP
  `cupel_audit`): one read-only report across six questions: possibly wrong
  tests, tests that catch no faults (or only because the code crashed), code
  that runs with faults unnoticed, tests of the same thing (across languages
  too), tests to combine (in a file and across files), coverage with unmeasured
  code apart, and where test time goes. It never advises removing a test.
- **Rust coverage on any OS** (rustup LLVM tools): tests run in Cargo's own
  directory and environment; programs started by tests, crates without tests,
  `#[should_panic]` and files compiled for other targets are handled.
- **Rust mutation through cargo-mutants** (D19): per-test catches with how each
  test caught the fault (`killKinds`), timeouts re-run, stale or unreadable runs
  refused; `cupel import --format cargo-mutants`.
- **`no-assertion` and `tautology` findings** for Rust, JavaScript/TypeScript
  and Python tests, reported only when certain.
- **Worker code in workerd** (S30, D18): per-test coverage rebuilt from
  never-pausing breakpoints, statuses and durations from a plain rerun, and
  fault testing in a scratch copy of the project.
- **Mixed-language repositories:** `builtInto` labels code another language's
  tests run (such as Rust in a WebAssembly module); opt-in `crossRunner`
  re-tests Rust survivors with the tests that load the artifact.
- **`guard --allow-runtime-change`:** explicit comparison across toolchain
  versions, with line checks reported as not compared.
- **Read-only:** a full `report` with fault testing leaves the assessed project
  byte-for-byte unchanged apart from Cargo's `target/`.
