# 0.3.0 release (2026-11-23)

npm package **0.3.0**, Python collector **0.2.0**. Faster fault testing with no
loss of evidence, a speed guide and a best-practice guide. Registry uploads stay
unapproved (L6); npm keeps `private: true`, Python `Private :: Do Not Upload`.

## What is new

- **Reuse of earlier fault results** (SPEC K15, D20). Every fault row gets a
  `basis`: a SHA-256 over its id, the passed tests that run its line, every project
  file those tests could read (sources and test files they never run are left out;
  `mutation.reuse.ignore` names others) and the toolchain. A `killed`, `survived`
  or `no-coverage` row whose basis is unchanged is copied (`reused: true`) instead
  of run, for node:test, Vitest, Jest, pytest and Rust (cargo-mutants). Locally the
  earlier input is `.cupel/input.json`; on CI machines that start empty, keep the
  input file in the CI cache and pass `--reuse <file>` (a missing file runs
  everything). `--no-reuse` and `"mutation": { "reuse": false }` switch it off.
- **pytest stops once two units have caught a fault**, as the JavaScript runners
  already stopped after two catching files; units a review asks about still run
  every test.
- **Rust (cargo-mutants)**:
  - lines no passed test runs are reported `no-coverage` without a build;
  - only the packages whose tests run the faulty lines, plus the package owning the
    faulty file, are tested (`--test-package`);
  - `maxMutants` and `seed` now apply, with the JavaScript sampling rule.
- **CLI**: `guard --out` saves the collected head for the next run;
  `guard --base-input … --changed <ref>` tests changed lines against a saved base;
  `--reuse` and `--no-reuse` on report, review, audit, check, guard and mutate.
- **Docs**: [Faster fault testing](../../docs/speed.md) (what Cupel skips, settings,
  reuse, recipes for pull requests, nightly and CI) and
  [Best practices](../../docs/best-practices.md); README, CLI, config, Rust and
  Python pages updated.

## Independent review

A fresh reviewer looked for ways the speedups could give a different answer than
a full run and found nine. All were fixed before release:

1. `guard`, `check` and `mutate` read `.cupel/input.json` from the checkout, so a
   change could plant forged rows. They now reuse only a file named with `--reuse`.
2. A row that stopped early could be reused where a reviewed unit needs every test
   run. Such mutants now always run (JavaScript and Python).
3. Cross-runner catches stayed reused after the JavaScript test changed. A row is
   now reused only when every catching test is in the fault's own run.
4. Rust: `no-coverage` rows for unrun lines can include faults that would not
   compile, and building one package alone can change Cargo features. Both are
   documented; `wholeWorkspace` restores testing every package.
5. Compiled languages, and tests that start programs or are end-to-end, now put
   every source into the fingerprint.
6. The fingerprint now includes git-ignored files outside dependency and build
   folders, installed-dependency records, submodules, files above a monorepo
   subfolder, symlink targets and more environment variables (`reuse.env` adds
   others).
7. Kill sets of units that were not targeted can be partial (in JavaScript since
   0.1, now also in Python). Audit U4 now groups by kills only targeted units;
   others group by lines (case 111).
8. Doc claims corrected (trust, "nothing is lost", counts).
9. `guard --changed` now refuses combinations where it would have no effect.

## Not verified

- Linux and Windows.
- Time saved on a real repository across two commits; the fixtures show that
  nothing is run when nothing changed, not a typical saving.
- A Rust fault on a line no test runs is reported `no-coverage` from cargo-mutants'
  listing, so a fault that would not compile can be counted there.
