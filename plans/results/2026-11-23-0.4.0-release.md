# 0.4.0 release (2026-11-23)

npm package **0.4.0**, Python collector **0.3.0**. Cupel's own Rust fault runner
and fault-test slices for CI. Registry uploads stay unapproved (L6).

## What is new

- **Rust: `runners.cargo.mutants.backend: "cupel"`** (D21). cargo-mutants' fault
  list and catch credit, run by Cupel:
  - only the test targets and tests that run the faulty line (B);
  - most relevant and fastest first, stopping after two catching targets (A);
  - faults the rewriter can bound exactly compiled into one build and switched with
    `CUPEL_FAULT` (C). Trust is decided per test target: a target whose tests behave
    differently with every switch off runs only on per-fault builds. Operator faults
    that would regroup the expression (`&&`↔`||` and other changes of binding
    strength) are never switched.
  - cargo-mutants stays the default backend.
- **Slices for CI** (D22):
  - `cupel mutate --plan` lists, per runner, the faults to run, reuse and skip, an
    estimate, and the suggested number of slices (default rule: one machine while
    the estimate fits 10 minutes, else enough slices to fit, at most 20);
  - `cupel mutate --runner R --shard I/N` runs one slice;
  - `cupel merge-mutations` joins slices and refuses mismatched, missing or doubled
    parts.
- **`durationMs`** on every fault that ran, which later plans use as the estimate.
- **Fix:** a JavaScript slice treated faults left out by `maxMutants` as complete
  evidence elsewhere; slices now merge to exactly the whole run's `targeted` units.

## Evidence

| Check | Result |
| --- | --- |
| Fixture workspace, three ways (cargo-mutants, Cupel with one build per fault, Cupel switched) | identical rows: status, catching tests and catch kinds |
| One critical 129-line file of a private Rust workspace, 90 faults | Cupel A+B: fault phase about 60 minutes (73 including coverage collection); 71 caught, 12 unnoticed, 6 timeouts, 1 untested line. cargo-mutants was estimated at about 3 hours for this file (not timed in this run) |
| Same input, Cupel A+B+C | identical statuses for all 90 faults; about 61 minutes. 60 faults switched, 29 regrouping faults on their own builds; one integration test target with a 100 ms time budget differed with switches off, so it ran only on per-fault builds |
| Where the time goes there | 8 faults caught by exactly one target cost about 235 s each (60% of all fault time): proving a catch is unique runs every covering target. Builds are not the bottleneck there |
| Two bugs found on that workspace and fixed before release | a switched-build check that only compared whole runs (now per target), and regrouping operators (`a && b && c && d` with one `&&` made `\|\|` means `(a && b) \|\| (c && d)` as text) |
| Rewriter tests | 41, including real `rustc` builds: switches off reproduce the original program's output |
| Slicing tests | rule, balance, merge refusals, CLI plan → two slices → merge equal to the whole run, `targeted` equal with and without a cap |
| Python mutation tests | plan, `only` and `durationMs` covered; same environment failures as `main` |
| Independent review | 10 findings, all fixed: writes through a symbolic link out of the scratch copy (now refused or replaced by a copy), target order from measured times (now from the input, so results repeat), Rust slices with uncompilable faults marked sampled, the switch module lost after a retry round, doctest wording, unlogged baseline failures, `-` before literals, two CLI argument checks, multi-file integration tests, and second variants split from their first |
| Full Node suite on the build machine | no new failures beyond the known missing-tool tests |

## Not verified

- Linux and Windows.
- cargo-mutants timed on the same input (the 3-hour figure is an earlier estimate).
- Slices on a real CI system; the commands are tested locally.
- Sharing one switched Rust build between slices (each slice builds its own).

## Next

A status-only mode for pull-request guards (stop at the first catch) would remove
most of the remaining Rust time, but the engine must never read partial catch
lists as complete. Not built; it needs the owner's decision.
