# S20: bounded Go mutation execution

## Decision and proof already obtained

The independent [compiled-language proof](s20-compiled/RESULTS.md) established that Go 1.27.1's `-overlay` compiles replacement bytes while a running test's `os.ReadFile` sees the pristine source. Its two smoke tests pass on Node 22.23.3 and 26.7.0. Rust/Cargo has a single-file crate-root proof only; general Rust language mutation and a Rust engine port remain separate, unproven work.

Implement one real Go mutation path now. This is not selective PR execution. The initial test oracle is ordinary whole-module `go test -json -count=1 -p=1 ./...`, so each Go package's tests share their normal process state. If that oracle disagrees with the collector's top-level test IDs or statuses, refuse the mutation request. Do not narrow the suite or silently switch runners.

## API and ownership

Add `packages/cupel/src/mutate-go/` with `mutateGo({ root, input, config = {}, scope = {}, log = () => {}, metrics })` and `confirmGo({ root, input, mutation, ids, config = {}, log = () => {}, metrics })`. Both return the existing input-schema mutation shape `{ mutants, targeted, seed, sampled }` (confirmation returns an updated copy). This slice does not wire the CLI, MCP, engine, or JS/Python/Ruby mutation code. The root agent owns integration after targeted tests pass.

The collector's `sources[path].hash` becomes canonical `sha256:<64 lowercase hex>` for every collected Go source; adding that value in `collect/go/index.mjs` is the only collector edit. Both mutation and historical confirmation require canonical hashes and matching raw source bytes, path identity, and Go runtime version before accepting a site. A missing, opaque, or stale hash is an error. Snapshot all declared sources at request entry and check again before and after baselines, mutant compilations/runs, retries, probes, and confirmation repetitions. Never change a project source file; write the mutant and overlay JSON only under ignored `.scratch/`.

## Boundaries and execution

1. Force `GOPROXY=off`, `GOSUMDB=off`, `GOTOOLCHAIN=local`; use the local Go toolchain and scratch outputs. No install or download.
2. Use `go list -json ./...` to bind source paths and top-level test files to module packages. Refuse cgo, `go:embed`, assembly and other nonstandard compiler channels, and declared tests that spawn another Go compiler. This first contract targets ordinary `.go` source and top-level `TestX` tests only. Refuse unknown or duplicate test IDs and any discrepancy between full baseline test results and the input.
3. A tiny standard-library Go AST helper parses retained source text from stdin and emits byte offsets/lines for a bounded operator set: comparison flip, `&&`/`||`, boolean literal flip, and `+`/`-`. Candidate IDs include source, line, byte column, operator, and a replacement hash. Sort sources and sites before seeded, capped selection. A compile-invalid mutant is excluded from results, never recorded as survived or killed.
4. Scope sources and coverable lines using the existing critical source rule, changed lines, and targeted units' own coverage lines. Apply configured include/exclude globs. Keep targeted units only when every eligible own-line mutant has a usable result; caps, deadlines, unsupported sources, or errors cannot create a false completeness claim.
5. Establish a full ordinary baseline. For each mutant, compile test packages with Go overlay to separate compile invalidity; then execute the full ordinary module test command with the same overlay. A kill requires a reported top-level failure from a test that passed in both input and baseline. Missing/unknown tests, process crashes, non-test package failure and unreported failure become errors. Timeouts remain timeouts without invented killers. Retry runtime errors/timeouts once with a fresh unmutated run, and use an unmutated known-good probe before attributing an environment-independent mutant error.
6. Re-run each survivor twice before returning it as survived. `confirmGo` also regenerates historical IDs from the current canonical pinned source and performs two further repetitions for requested survivors; any changed source or identity refuses confirmation. Enforce `maxMutants` and `maxSeconds` without altering the test set or heap.

## Acceptance gates

- Fresh fixture: a behavior mutant is killed, a nonexecuted mutant survives, a source-text pin stays passed, and source hashes remain byte-identical.
- Invalid replacement is excluded; malformed/missing hash, changed source, unsupported cgo/embed/compiler channel, or baseline ID/status mismatch refuse explicitly.
- Sampling, changed-line and targeted scope, caps and `targeted` completeness are deterministic. Schema/integrity accepts the returned mutation; a real mutation loss causes guard loss data rather than a fabricated green.
- Run focused tests on Node 26 and Node 22. No broad speed claim or Rust/Go selective PR claim follows from the fixture. Whole-call performance and a real repository remain separate acceptance gates.

## Measured implementation result (2026-10-25)

The implementation lives in `packages/cupel/src/mutate-go/`, including a standard-library Go AST helper. `collect/go/index.mjs` now attaches canonical raw-byte hashes. CLI/engine wiring is outside this slice. The no-dependency fixture has four ordinary top-level tests plus a dormant source-write control. The selected two arithmetic sites gave **one reported kill** (`TestChoose`) and **one executed survivor** (`TestIdentity`, `n + 0` to `n - 0`). `TestSourcePin` read pristine `value.go` and was never credited as a killer. The survivor remained survived after two repetitions inside `mutateGo` and two further `confirmGo` repetitions. A fabricated historical survivor for the killed site was redetected, while the other mutant and targeted units remained unchanged. A guard comparison of the actual killed mutant against an artificially survived head reported that mutant in `critical-mutation.lost`.

The separate negative cases verified: one string-addition mutant that does not compile was excluded; a partial top-level inventory refused; embed/build tags, a cgo metadata channel and custom `GOFLAGS` refused; wrong Go runtime refused; a process abort without the complete reported test set remained `error` with no killer; a cap of one site sampled deterministically and marked only its complete targeted unit; function/body scope refused. Missing or stale canonical source hashes refused confirmation. The test also changed a scratch fixture's production source **before and during baseline**, **during mutant execution**, and **during historical confirmation**, plus its test file during baseline; every change was refused through raw hash/path checks.

Focused tests: `node --test packages/cupel/test/mutate-go.test.mjs` passed **8/8** on Node **26.7.0** and **8/8** on Node **22.23.3**; `npm run check` passed. The helper's `GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local go test ./...` passed. An existing `collect-go.test.mjs` run was **4/5** while concurrent CLI work refused Go mutation by design; its CLI expectation belongs to that integration and is not counted as a Go mutation pass. These are correctness smoke tests, not a latency benchmark.

## Remaining limits and verdict

**Go mutation is a verified, narrow internal profile**, not a general language or selective PR claim. It is restricted to Go **1.27.1** on the tested native host, ordinary `.go` source and top-level tests, and the four AST operator families in this plan. It runs every module package serially (`-p=1`), retaining state within each package but changing cross-package scheduling relative to Go's default. It explicitly rejects workspaces, custom compiler flags and cross targets, cgo/embed/assembly, build or line directives, unsupported function scope and partial test inventories. External module cache identity, native I/O, indirect subprocesses and shared state beyond the fixture were not validated. Tests themselves are not network-sandboxed; only Go's module/toolchain resolution is forced offline.

Request-local source and test files are rehashed and path-checked around each child process. The collected input hashes **production source files only**. It carries no previous full hash of test-file bytes, so a changed assertion that still passes the current baseline can escape cross-request historical test-code identity. `confirmGo` must be described as regenerating mutants against pinned production bytes and rechecking the **current** complete test suite, not as proof of unchanged test code since collection. A separate provenance extension is needed before claiming that stronger guarantee.

Next best action after this internal profile: complete private artifact and full-suite gates, then run a real-repository acceptance workload. Keep Go selective PR execution separate and test its native I/O and shared-state boundary before enabling it. Rust language mutation still needs the multi-file/macro proof; a Rust engine port remains deferred.

## Native CLI and private npm integration

The CLI now lazy-loads `mutateGo`/`confirmGo` for the `go` runner and uses the Ruby backend's exact configured collector command prefix for `minitest` `mutate`/`confirm`. The Ruby command must end in `collect`; there is no substituted command. Go and Ruby function-only mutation remain unsupported, and Cargo, unknown custom runners and mismatched runtime/runner pairs still refuse. Mixed-runner mutation preflights every requested part before calling any mutator; confirmation retains per-part targeted units. Saved inputs and `--no-mutation` remain read-only/coverage-only paths.

The canonical Ruby `packages/cupel-ruby/bin` and `lib` trees are mirrored under `packages/cupel/ruby/`, listed in npm `files`, and compared path-by-path and byte-by-byte by `scripts/ruby-runtime-parity.test.mjs`. `scripts/sync-ruby-runtime.mjs` materializes the copy explicitly after canonical changes. The CLI uses only the bundled Ruby path in both source and installed npm layouts. `npm pack --offline --ignore-scripts` includes the runtime; no install hook or sibling checkout is needed.

Targeted Node 26 CLI/collector/parity gate: **16/16 passed**, including real Go and Ruby `report`, saved-input/`--no-mutation`, and Git `guard` loss tests. The same native CLI/capability/parity subset on Node 22.23.3 passed **9/9**. Ruby backend tests passed **35 runs, 148 assertions**. The required installed-artifact gate `CUPEL_REQUIRE_RUBY_SMOKE=1 CUPEL_REQUIRE_GO_SMOKE=1 node --test --test-name-pattern='npm tarball installs offline' scripts/package-smoke.test.mjs` passed **1/1** with the real offline npm tarball: Ruby reported **2 base kills and 2 guard losses**, Go **1 base kill and 1 guard loss**. `npm run check` passed. The root agent owns the full `npm run verify` and final private artifact gate; those are not asserted here.

The collector's pre-existing Go environment was found to inherit `GOTOOLCHAIN` and caches while forcing `GOPROXY/GOSUMDB=off`; `docs/go.md` now says so. Go mutation separately forces `GOTOOLCHAIN=local`. No Go/Ruby selective PR safety or whole-call speed claim follows from these CLI fixtures.

## Go safety freeze (2026-10-25)

Root review identified three further refusal boundaries. All source and `go list` file names now reject credential/private path components, and every declared file passes canonical regular single-link metadata checks before **any** source or inventory content read. The new test placed a private file or a late-listed symlink after an ordinary file and measured **zero reads**. Go child commands start in a new POSIX process group; timeout and 16 MiB output overflow send `SIGKILL` to that group and wait up to five seconds for pipes to drain. Unsupported hosts refuse. A descendant-write fixture stopped while an unrelated child wrote its marker. This does not prove containment for a descendant that starts a new session or bypasses the inherited pipe group.

A failing overlay compile is excluded only when a known-good unmutated compile succeeds and the Go compiler emits a syntax/type diagnostic naming the target source or its exact scratch overlay backing file. Signals, disk/tool errors, missing or unrelated diagnostics refuse as environment errors. Go 1.27.1's actual invalid fixture reported `./.scratch/.../source-1.go:7:30`, which is why the backing file is included. The conservative diagnostic recognizer may refuse an unfamiliar genuine compiler error; it does not silently count it as a valid mutant.

After these fixes, `node --test packages/cupel/test/mutate-go.test.mjs` passed **11/11** on Node **26.7.0** and **11/11** on Node **22.23.3**. The Go CLI report/saved-input/Git-guard integration test passed **1/1**, and `npm run check` passed. The root agent still owns the broader suite and private installed-artifact gate after freeze.
