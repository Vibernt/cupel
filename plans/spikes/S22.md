# S22: MRI/Minitest in-memory mutation

## Decision-complete implementation plan

**Boundary.** Support only pinned MRI Ruby 4.0.7 and Minitest 6.0.0. The collector remains an external process and keeps the ordinary Minitest test-file command and Bundler setup. Reject other runtimes, unsupported custom loaders, wrapped `load`, unresolved test selections, missing source loads and unsafe source paths. No gem download, package dependency, original-source write, or network call.

**Source identity.** Extend Ruby source records with SHA-256 of raw bytes. Require the input hash to match a regular, single-link, in-root non-symlink source before reading mutation content, and recheck identity after every baseline, mutant, retry and confirmation subprocess. Reject path or byte changes even if the same mutant id still exists. Keep mutation specs and load receipts in private `.scratch` files.

**Loader proof gate.** Intercept `require` and `require_relative` in the Minitest subprocess. Compile one replacement source with `RubyVM::InstructionSequence.compile(replacement, original_absolute_path, original_absolute_path, 1).eval`; retain the original path in `$LOADED_FEATURES`. A proof must show changed execution, correct `__FILE__` and `require_relative`, and an unchanged raw SHA-256 and source-text pin. If this proof fails, stop without a disk-written mutant substitute.

**Sites and scope.** Use Ripper token offsets and Ruby syntax compilation to generate deterministic one-token numeric, boolean and comparison changes. Mutant ids include source path, operator, location and original token, and remain stable for identical source. Exclude syntax-invalid candidates. Select source lines by `critical`, `changed`, and `targeted` inputs, intersected with coverable lines and configured scope. Prefer complete targeted units within `maxMutants`, then seeded deterministic sampling; report `sampled` and mark a unit `targeted` only when all its own-line sites ran. `maxSeconds` cuts the work without inventing an outcome.

**Evidence.** Select baseline-passed Minitest rows covering the site, including setup-attributed rows. Run the same Minitest setup and exact row names in a fresh subprocess for baseline and mutant. A kill requires a reported test failure absent from the baseline. A startup failure or process crash is `error`, an unobserved mutant load is `error`, and a timeout requires a known-good unmutated probe before it can be reported. Retry crashes once. Confirm selected survivors twice against canonical source hashes; a late kill supersedes survival.

**Interface and verification.** Add `mutate --root --input --scope --config --out` and `confirm --root --input --mutation --ids --config --out`. Return the standard mutation object for CLI dispatch. Add tests for the loader proof, source pin, killed/survived/confirmation, same-id source changes, lost-kill guard shape, runtime and loader refusal. Run the Ruby full suite. Do not claim selective PR execution from this spike.

## Initial proof

On Ruby 4.0.7, a private `.scratch` test compiled replacement source under the original filename. The runtime value changed from 10 to 11, `__FILE__` and `require_relative` resolved to the original file, and the on-disk SHA-256 and source-text pin remained pristine. This establishes the narrow loader mechanism, not adapter completion.

## Method and results

Ran the direct conformance fixture through `collect --runs 1` and `mutate` with `changed: {"lib/math.rb":""}` and `maxMutants: 4`. It produced 3 mutants, all `killed` by reported baseline-passed Minitest rows, `sampled: false`, and no target units requested. The private loader proof changed a value from 10 to 11 while preserving the original file hash and path metadata.

The Ruby package suite on MRI 4.0.7/Minitest 6.0.0 passed **35 tests, 148 assertions, 0 failures, 0 errors, 0 skips**. Coverage includes a source-text pin that does not kill, original `__FILE__` and relative requires, a duplicate require, Unicode before a mutation token, survived and twice-confirmed mutants, a same-id killed-to-survived lost-kill shape, source changes before and during baseline/mutant runs, linked and symlinked source refusal, invalid syntax and unsupported runtime refusal, `load` and wrapped `load` errors, critical and targeted scope, seeded sampling and complete-target accounting, crash retry, timeout and failed known-good probe, and the CLI mutate/confirm JSON contract. The policy test also checks the default critical path words against the canonical config schema and exercises Unicode final-sigma behavior shared with the JS engine.

A subsequent safety review found and closed five gaps: a timeout now needs a fresh mutant-load receipt, a passing unmutated probe and a larger-limit mutant retry; crash retries receive distinct private receipts; critical-path Unicode tokenization and loose globs follow engine section 5; file-level coverage is explicitly refused; and confirmation checks the pinned runtime and regenerated site metadata. New negative cases show that a pre-load timeout and a stale retry receipt cannot earn a detection. The pinned Ruby suite result above includes these cases.

**Verdict:** the pinned direct-file MRI/Minitest mutation backend is implemented and passes its local tests. It is eligible for the repository's full verification and root CLI integration. It does not establish Rails, Rake, alternate MRI/Minitest versions, custom loaders, real-repository acceptance, selective PR safety, or installed-artifact behavior. These cases need separate evidence before claiming support.
