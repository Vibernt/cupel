## Part 2: A/B protocol

The four task prompts in [tasks.json](s8/tasks.json) target real S3 survivors: permissions delegation depth and expired parent, agent-connect race/orphan revocation/per-address guesses, billing-ledger re-send window/dead-letter alert, and the billing low-balance ratio. Both arms add tests only under `tests/*.test.mjs`, cannot edit `src/`, and do not use the network or install dependencies. The `cupel` arm adds the requested `cupel_check` instruction. Both arms use `--approve-for-me` so approval policy is held constant. The Cupel arm alone configures the MCP server with `/opt/homebrew/bin/node` and `/Users/vid/cupel/packages/cupel/bin/cupel.mjs mcp --root <copy>`.

Use three independent repetitions for each task and arm: 24 fresh Assay copies, 12 paired comparisons. For each `task` in `permissions`, `agent-connect`, `billing-ledger`, `billing-threshold`, and each `rep` in `1`, `2`, `3`:

```sh
node plans/spikes/s8/ab.mjs prepare "$task" plain "$rep"
node plans/spikes/s8/ab.mjs prepare "$task" cupel "$rep"
```

`prepare` archives the pinned Assay tree, runs its build, adds the exact test glob to `cupel.json`, and creates one baseline commit in each **new Assay copy**. It then writes `prompt.md`, `.s8.json` and an executable `command.sh`. The Cupel command line in that file is equivalent to:

```sh
codex exec -C '<copy>' -c 'mcp_servers.cupel.command="/opt/homebrew/bin/node"' -c 'mcp_servers.cupel.args=["/Users/vid/cupel/packages/cupel/bin/cupel.mjs","mcp","--root","<copy>"]' --approve-for-me --json - < prompt.md > codex.jsonl 2> codex.stderr
```

Run each arm later from its copy with `./command.sh`; `ab.mjs` never starts agents. The command also writes `arm-timing.json`. After an arm completes:

```sh
node plans/spikes/s8/ab.mjs measure "/Users/vid/cupel/.scratch/s8/${task}-plain-${rep}"
node plans/spikes/s8/ab.mjs measure "/Users/vid/cupel/.scratch/s8/${task}-cupel-${rep}"
node plans/spikes/s8/ab.mjs summarise
```

`measure` compares each copy with its baseline commit for new test definitions and added test lines; collects the Assay test glob; resolves the new IDs from actual collector output; scores them with `cupel check --no-mutation`; and records whether they pass. If they pass, it mutates the task module with `scope: { critical: false, targeted: [], changed: { [module]: '' } }`, seed `20261021`, a 30-minute ceiling, and a cap covering that module (150 for permissions/agent-connect, 250 for domain billing, 400 for billing-ledger). It joins the resulting mutants to the 109 S3 survivors by file, line, column and operator, and counts only kills attributed to new test IDs. A read-only check against `assay-main` matched all 109 S3 survivor positions to one current mutant each. It records sampling, unmatched mutants, source edits, arm wall time, and `turn.completed` input/output token usage from `codex.jsonl`. A sampled or failed mutation run cannot establish complete survivor-kill parity. `summarise` writes [summary.md](s8/summary.md).

The primary outcome is the number of **hand-judged truly redundant new tests** per arm, with the coverage `adds-nothing` count as a separate proxy. Inspect every `adds-nothing` verdict and its `extend` target; review the new tests' assertions and the S3 survivor kills before judging redundancy. Reject a pair from outcome comparison if either arm changes `src/`, has failing new tests, lacks complete collection or mutation, or lacks the required Cupel tool call in the treatment log. Report exclusions and raw per-pair counts. A positive launch claim requires at least eight informative non-tied pairs, a one-sided exact paired sign test at `p <= 0.05` favoring Cupel on truly redundant counts, a lower pooled redundant share, no lower pooled S3 survivor kills or new-test pass rate, and a hand-checked `adds-nothing` false-positive rate no greater than 10%. Otherwise the result is inconclusive or negative, with the observed counts shown.

**Verdict for part 1.** Coverage-based "adds nothing" was wrong for 23 of 24 new agent tests, a 96 % false-positive rate, so the redundancy rate measured by coverage (35 %) is not the real one. Judged by assertions, about 1 in 69 (1.4 %) of these agent-written tests was redundant.

These agents mostly add tests that check new behaviour on code that other tests already run: boundaries, tenancy, expiry, exact orderings, request lists. This repeats S6's finding with a second judge and fresh data.

**Implications.**
1. **`cupel check` must not say `adds-nothing` on coverage alone.** It should mirror D5:
   - a test with no unique lines gets targeted mutation of its own lines;
   - it adds value if it uniquely kills a mutant;
   - otherwise the verdict is `no-unique-coverage-unverified`, a review hint, never "adds nothing".

   This needs a spec change to C2, proposed separately.
2. **Part 2 (A/B) must judge value by mutation kills and assertions, not by coverage verdicts.** Its `measure` step already runs mutation on the task module.
3. **The launch story changes.** On this repo, agents are not adding many no-value tests. Cupel's value for them lies in the guard (S4), the mutation gaps (S3), and an honest "unverified" rather than a false "redundant".
