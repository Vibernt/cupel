# S18 — Pinned saved baseline for incremental selection

Date: 2026-10-25. Status: experimental implementation and validation measured;
not promoted as a latency optimization.

The owner explicitly requested faster selection using saved/cached information
and incremental work. The existing S16 prototype saves evidence but rereads the
baseline checkout and installed dependencies on every request. S18 separates
historical baseline preparation from current HEAD validation.

## Prepare once

`prepareSealedBaseline` captures a real baseline, uses the existing validators
against its actual checkout, verifies collector/full parity, canonical source
hashes, critical labels, dependency observations and privacy proof, then writes
a versioned root-independent JSON artifact. Return its raw-byte SHA-256, with
commit, runtime/config/policy/schema and preparation-producer identity.

The artifact is historical evidence, not a live HEAD result. The expected hash
must come from an independently trusted caller. Hashes establish integrity
relative to that pin, not authenticity; CI artifacts/pins remain outside the
proposing agent's write scope.

## Consume explicitly

`runSealedSelectedHead` requires artifact path, expected artifact hash, expected
base commit, expected S18 producer hash, HEAD root, Node executable, explicit
input policy and private output path. It accepts no baseline root, loose bundle,
caller snapshot or validated-context flag.

Read/hash/parse the artifact once per request. A new sealed verifier checks
version, schema, canonical saved inventories, all bindings, critical labels,
dependency metadata, original profile proof and preparation identity using the
saved inventory. It must not call the original directory-reading verifier with
a fake baseline root or suppress a failed validation.

Missing, corrupt, truncated, stale or incompatible artifacts error explicitly.
There is no automatic capture, rebuild or alternative execution path.

## HEAD remains current

Reuse unchanged S16 capture/assessment primitives through a new coordinator and
truthful composite source identity. Maintain fresh HEAD pre/post content reads,
lock/installed dependency identity, exact Node binary/runtime, config/policy,
selected test execution, denial/completion checks and producer validation.
Derive the full HEAD test inventory from current files, including supported new
tests. Preserve critical/new-test selection, source-text readers, non-code full
route and unknown-source refusal. No cached test pass becomes a current pass.

Dirty local HEAD is checked by contents, never timestamps alone. S18 does not
add a persistent HEAD index, readonly-worktree assumption, scheduling change,
general result cache or Rust dependency.

## Gates and measurements

Implementation stays under `plans/spikes/s18/`; S16's frozen source is unchanged.
Verify its current reference closure before freezing a new S18 composite hash.

- Actual tests on Node 22/26: artifact missing/wrong pin/truncated JSON, changed
  commit/config/runtime/dependencies/policy/schema/producer, missing canonical
  hashes, altered critical tags, incomplete privacy proof and caller injection.
- Make baseline checkout unavailable after preparation and prove consumption
  reads zero baseline source or installed dependency files.
- HEAD byte change with preserved size/mtime must still be detected; selected
  rows, faults, required refusals and source-text control match the oracle.
- Keep the complete 65-test Express lane and both real faults. Five alternating
  whole-call S16/S18 and S18/privacy-guarded-full pairs, with no CPU interference.
- Include artifact read/hash/parse and all HEAD/proof checks in repeated-use cost.
  Report preparation separately and show amortized cost over repeated requests;
  do not hide one-time work or promise speed from test-count reduction.

## Measured verdict

The four Node 22/26 × strict/opaque oracle matrices passed their 15 cases
each; every consume request used a sealed artifact while its baseline checkout
was unavailable. See [s18/MATRIX-RESULTS.md](s18/MATRIX-RESULTS.md).

On the unchanged 65-test, four-file public Express unit lane, five alternating
Node 26 pairs per fault gave whole-call S16→S18 medians of **338.67→287.07 ms**
and **250.45→208.68 ms**, with S18 faster in 5/5 pairs for each. Against
privacy-guarded ordinary full execution, S18/full medians were
**288.99/136 ms** and **208.95/137 ms**; S18 was faster in **0/5** pairs for
either fault. Thus saved-baseline selection is faster than S16 but does not
beat full execution for this real lane. The artifact preparation call took
911.72 ms; the separately verified saved collector input and pin took another
86.38 ms. Original collector generation was not run in S18, so complete cold
setup is unavailable. Detailed phases, paired raw locations, and N=1/10/100
amortization are in [s18/measure/RESULTS.md](s18/measure/RESULTS.md).

Next best action: keep S18 experimental, complete the full correctness gates,
and profile the identified `Session.select` repeated coverage parsing before
one bounded cache change. These numbers do not justify shipping selective PR
mode on latency grounds or claiming a general speedup.
