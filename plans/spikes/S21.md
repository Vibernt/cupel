# S21: Python mutation source freshness

## Decision-complete plan

The Python mutation runner currently enumerates byte-offset edits from one source read, then its pytest loader rereads the source for each mutant. A same-ID edit elsewhere in the file can therefore apply a valid offset to different bytes. Source IDs are not whole-file identities.

1. Add a standard-library, per-request source ledger. Reject noncanonical/private paths, escapes, hard links, nonregular files, changed project root, and hosts without `O_NOFOLLOW` before reading source content. Bind a retained fact to logical and real path, device/inode and SHA-256 of raw bytes. Validate optional canonical input hashes before enumeration, and require them for confirmation because a prior mutation report does not carry a whole-file pin.
2. Recheck every retained source before and after each pytest execution, including baseline, mutant retry, timeout recheck and confirmation. The child loader also verifies its exact source fact before applying offsets. Refuse any mismatch as an environment error; never classify it as a kill or silently regenerate a mutant. Keep only source facts across runs, never outcomes.
3. Add negative controls for path/hash failures and source writes during baseline, mutant and confirmation. Add a same-ID surrounding-text edit and a positive pinned-source confirmation. Run targeted Python tests in the existing offline pytest environment, then report counts and limitations.

No network, package installation, changes to protected sibling repositories, or publication are part of this spike.

## Results and verdict

Implemented the request-local ledger in `mutation_source.py` and wired it through source enumeration, every pytest launch, the child mutant loader and confirmation. The ledger retains source text and raw SHA-256, logical/real path, project real path and device/inode, subject to a 32 MiB retained-byte cap. It does not retain mutant outcomes. Confirmation refuses handcrafted input without a canonical source hash; collected Python input already has one. This is an intentional compatibility limit because an ID can stay the same after another line changes.

The existing offline Python 3.14.8 / pytest 9.1.1 environment ran **45 package tests plus 4 subtests**, all passing in **20.22 s** after the final freshness check. The focused mutation file ran **23 tests plus 4 subtests**, all passing in **14.37 s**. New actual-pytest controls changed source during baseline, mutant execution and confirmation; each raised `SourceChangedError`. A same-length, same-mtime edit kept the mutant ID but was refused by the declared whole-file hash. Path, hard-link, opaque-hash and fact-cap negative controls also passed. Existing mutation output, retry, sampling and positive CLI confirmation tests passed.

This verifies the local Python package and its pytest subprocesses. It does not verify a wheel rebuilt from these edits, Windows path behavior, or a cross-repository runner. No source files under the protected sibling repositories were modified or executed.

Next best action: integrate this safety correction with the CLI runner-capability work, then run the full repository gates and offline installed-package smoke before the selective PR acceptance gates.
