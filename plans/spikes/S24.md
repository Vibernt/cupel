# S24: bounded Python selective profile

## Decision-complete implementation plan

Owner-approved mode: opt-in `pytest-readonly-files-v1`, independent test-file processes for both full baseline and selected execution, retaining pytest's per-test `sys.monitoring` coverage. Unsupported suites refuse; there is no automatic isolation switch. The ordinary full guard remains separate.

1. Probe Python 3.14.8's standard audit events for read, missing-file probe, directory listing, process/network/native-load, and write channels **before changing the runner**. The profile may proceed only if the required channels can be observed or refused before project code, conftest and config run, with caught denials recorded. A missing required channel blocks this profile; no hook-skip or alternate execution policy is introduced.
2. If the probe passes, implement a small `pr_profile/` backend. Bootstrap in a fresh Python process before pytest config, constrain nonsecret environment/private temporary writes, pin source/config/dependency/runtime identity before and after each file, collect actual pytest rows and per-test `sys.monitoring` buckets through the existing collector, and return versioned evidence with provenance, traces, capabilities and errors. Parent checks completion and all identities.
3. Compare ordinary full execution under the same independent-file policy with constrained full execution for exact IDs/status/coverage parity. Demonstrate a clean strict-subset selection and the original source-read fault, and refuse shared-state and caught unsupported-channel controls. Exercise setup, teardown, parameter IDs, source pins and private-path metadata refusal before content reads. Report total launch/time/memory costs separately.

No package installation, network, protected sibling-repository execution, CLI/MCP promotion or private package replacement is authorized in this slice.

## Probe and verdict

Ran one bounded audit-event probe in the existing offline Python 3.14.8 environment. It used a fresh temporary project file and a missing sibling. `Path.read_text()` and `os.open()` emitted `open`; `os.listdir()` emitted `os.listdir`; `os.scandir()` emitted `os.scandir`. A missing-file `Path.exists()`, `os.stat()` and `os.access()` each emitted **no audit event**. The probe made no network call.

This is a concrete blocker for the required failed-probe dependency trace. A test can branch on the absence of a file without an observed path edge. If another change creates that file, a selected run can omit the affected test. The audit hook also cannot persistently deny or record a caught failed-probe operation that it never observes. S12b's Python pilot explicitly tested missing-file probes, so dropping that edge would weaken its evidence boundary.

**Verdict: profile implementation blocked at the probe gate.** No `pr_profile/` production code or selective CLI/MCP claim was added. A wrapper around `Path.exists()` alone would leave other C-level stat/access paths and bypasses unproven; adding such wrappers as a silent safety substitute would violate the requested complete-trace contract and the no-fallback rule. The decision needed from the owner is whether to authorize a separately specified and tested enforcement boundary for Python filesystem metadata calls, or defer the Python selective profile. Until then the ordinary full pytest collector and full guard remain the supported route.

Next best action: review the missing audit events and choose an enforceable boundary before implementation. Any revised profile must first prove failed-probe capture/denial before subject imports, then pass full-profile parity and strict-subset fault tests.
