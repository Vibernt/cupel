# S12 — Does selective PR execution miss failures?

Date: 2026-10-25. Status: **failed safety gate; PR mode blocked**.
Decision: D16. Owning plan: `plans/RELEASE-READINESS.md`.

## Question and boundary

Compare a deliberately broken head with a passing, full baseline. Does a
coverage-guided selection ever look green when a full run catches the fault?
This spike is experimental and does not add a shipping CLI/MCP PR command.
Existing full `guard` remains authoritative.

## Frozen initial contract

- Bind baseline evidence to the exact base tree, configuration, runtime, runner
  and full test inventory. Missing/corrupt/stale/mismatched evidence is an error.
- Select whole test files whose tests or setup covered any changed source file,
  critical tests, and every new/changed test file. No line-number narrowing.
- The D16 route for non-code inputs explicitly runs the full suite, with a reason.
  Unsupported source changes and unknown evidence must stop explicitly; do not
  silently replace the baseline or choose a different collection strategy.
- Preserve removed/renamed critical-test protection. A missing row is not a pass.
- Never splice unexecuted baseline tests into a report as passed at head.
- Selection timing and changed-critical-line mutation are separate measurements.

## Matrix and oracle

Use deterministic small fixtures for node:test, Vitest, Jest and pytest, with clean
controls. Every injected change has a full-suite oracle. Cover ordinary source
regressions; new branches/calls; shared setup/helpers; new failing and changed
parameterized tests; critical removal/rename; source deletion/rename/line shifts;
fixture/config/dependency changes; and tampered/stale/unsupported baselines.
Include source-text-reading tests, because executing `readFile` does not give
runtime coverage of the file it reads.

Record full failure, selection decision, selected IDs/files, actual selection
outcome, refusal reason, setup/full/selected wall time and false-green count for
each case. Count a case only if its oracle ran. Unavailable runners are blockers,
not skips presented as successful acceptance.

After the synthetic matrix passes, inject two faults per available launch runner
in real scratch suites (eight cases). Scratch sources only; original Assay and
CodeCrystal checkouts stay read-only. A synthetic pass alone is insufficient to
ship PR mode.

## Gate

Zero false greens among full-suite-detected faults, explicit rejection of bad
evidence and unsupported selections, all changed/new tests exercised, and passing
clean controls. Any miss blocks shipping selective PR mode. Preserve the failing
case and propose a bounded correction for Astra's review. Record speed only from
measured repeated executions; selected shares and summed durations are estimates.

## Method

The experimental harness is `s12/run.mjs`, `s12/fixtures.mjs` and
`s12/selection.mjs`. It does not implement a shipping PR command. For each
runner, it makes a scratch base with ten passing tests in eight files, performs
one actual full baseline run, collects Cupel's per-test input, then makes a
fresh scratch head for each fault. The base evidence binds SHA-256 hashes of
the entire fixture file inventory, the collector input and exact test IDs to
the runner, runtime, execution config and tier config. It checks Cupel's source
hashes and uses the engine's own `label` result for critical files, including
name, path and config tier rules. Missing, stale or altered identity refuses.

Each head runs the actual complete test suite as oracle. The experimental
selector chooses whole files with baseline per-test, per-file or setup coverage
of a changed source file, plus critical and new/changed test files. Non-code
inputs take an explicit full-suite route. Missing or unknown source coverage,
source removal/rename, critical test removal/change and invalid evidence
refuse. A selected decision then runs the named test files; it does not mark
skipped tests as passing. Runner output and wall time for both executions are
saved under `.scratch/s12/<runner>/`. The 15 cases per runner cover clean,
ordinary regression, new branch, setup, new test, changed parameter, critical
removal, source removal/rename and line shift, config input, unknown source,
stale/corrupt baseline, and source-text pin with unrelated executable coverage.

Runtimes were local and offline: Node 26.7.0; Vitest 4.1.11 linked from the
read-only CodeCrystal dependency tree; Jest 30.2.0 from the scratch runtime
with the actual Cupel Jest collector; and pytest 9.1.1 from the isolated
scratch Python runtime. All candidate source mutations were in `.scratch/s12`.
The Vitest fixture linked package entries into its own `node_modules` so Vite
temporary files stayed in scratch. No candidate checkout was changed.

Reproduce each runner separately with `node plans/spikes/s12/run.mjs node`,
`vitest`, `jest` or `pytest` as the final argument. Exit 1 is expected when
the preserved false green is reached; the script stops that runner at the
counterexample and writes its JSONL and logs first.

## Results

| Runner | Baseline tests/files | Base run + evidence setup | Cases | Full-oracle failures | Selected/full/refused | False greens |
|---|---:|---:|---:|---:|---:|---:|
| node:test | 10/8 | 245 ms | 15 | 10 | 8/1/6 | 1 |
| Vitest | 10/8 | 799 ms | 15 | 10 | 8/1/6 | 1 |
| Jest | 10/8 | 1,779 ms | 15 | 10 | 8/1/6 | 1 |
| pytest | 10/8 | 395 ms | 15 | 10 | 8/1/6 | 1 |

The same false green occurred in all four runners. `src/text` is executed by
`text-runtime.test`, which asserts only its type. `text.test` reads the same
source as text and asserts the literal `green`. Changing it to `red` makes the
full suite fail one test. Baseline executable coverage selects the critical
test and `text-runtime.test`, omits `text.test`, and that actual selected run
passes. Per-run evidence:

| Runner | Full wall / outcome | Selected wall / outcome | Selected files |
|---|---:|---:|---|
| node:test | 105 ms / 1 fail | 89 ms / pass | critical, text-runtime |
| Vitest | 355 ms / 1 fail | 314 ms / pass | critical, text-runtime |
| Jest | 374 ms / 1 fail | 249 ms / pass | critical, text-runtime |
| pytest | 175 ms / 1 fail | 157 ms / pass | critical, text-runtime |

The earlier cases caught ordinary source, branch, setup, new-test,
parameterized and line-shift faults; config took the full route; critical
removal, source deletion/rename, unknown source and invalid evidence refused.
All 60 full oracles ran; 40 detected faults. The false-green count is **4/40
full-oracle-detected faults**, one per runner. Clean controls passed. Exact
per-case outcomes and timings are in ignored
`.scratch/s12/results-{node,vitest,jest,pytest}.jsonl`, with full and selected
logs and baseline evidence in `.scratch/s12/<runner>/`. Each case records
selected baseline IDs and files; a new file has no baseline ID and is listed
separately until its actual run discovers the new tests.

The source-text hazard cannot be resolved by Cupel's current brittleness rows
alone: the Node and pytest inputs flagged this pin, while the Vitest and Jest
inputs did not. A bounded next experiment would establish a cross-runner
source-text dependency map and refuse selection whenever a changed source has
an unproven text-reading dependent test. It must re-run this exact four-runner
counterexample before shipping. This is a proposed correction, not a tested
fix. The intentionally conservative refusal for changed critical files also
needs a head test-ID check before it can support safe edits to those files.

No real-repository scratch acceptance was attempted after this synthetic gate
failed, as the frozen plan permits stopping at the first counterexample.
There is no practical speed claim: each synthetic case ran once, the suites
are tiny, and selection setup cost is material. Changed-critical-line mutation,
Node 22 and production CI behavior were not measured. **Verdict: do not ship
selective PR mode.** Keep full `guard` authoritative. Astra's final review
concluded that more research is not release-value work now: retain this evidence
and leave D16 blocked. Dependency tracing is a possible future investigation,
not a validated correction or automatically authorized follow-up. Concluding a
release candidate without selective PR mode needs the owner's scope decision.

The owner subsequently asked to make selective PR mode work and validate it if
possible. A bounded dependency-evidence follow-up is now authorized. This does
not change S12's failed verdict or authorize an unproven production selector.
