# S13 — Can an agent use the cleanup evidence without deleting useful tests?

Date: 2026-10-25. Status: bounded review completed; no cleanup-efficacy result.

## Method

The implementation agent ran the current `cupel review` CLI on the retained
browser-tools-mcp input, with `--limit 3`, then read all three named test bodies,
their surrounding setup and the production `resolveDestination` implementation.
The source checkout was read-only. This is a real agent review of real tests,
using historical collection evidence; it is not a fresh report or a controlled
comparison between agents.

Command (from this checkout):

```
node packages/cupel/bin/cupel.mjs review \
  --input .scratch/bench/repos/browser-tools-mcp/.cupel/input.json \
  --limit 3 --json
```

The saved pack is `.scratch/release-readiness/agent-review.json`.

## Decisions

All three candidates were standard-tier members of same-shape group g1, had zero
unique covered lines and zero recorded mutation kills. Those observations did
not establish redundant assertions.

| Candidate | Assertion and scenario | Decision |
|---|---|---|
| classifies a host by its worst address | A public and a private DNS answer must classify as private | Keep: checks worst-address ordering |
| returns every address so the proxy can try them in order | Both loopback families must be retained in input order, plus loopback classification | Keep: checks the returned address list, not only classification |
| make a name that resolves to one loopback too | A DNS answer matching the mocked machine interface must classify as loopback | Keep: checks local-interface recognition under separate setup |

The production function returns both an address list and the worst classification;
local interfaces affect classification. Removing any of these assertions would
lose a distinct scenario. Moving the third into a common table would also need
to preserve its enclosing mocked interface setup. There was no source-grounded
cleanup to make within the three-candidate budget, so none was forced.

## Verdict and limits

**Useful review context and restraint; cleanup efficacy unproven.** Three tests
reviewed, three retained, zero source changes, zero tests removed. No runtime or
line-count saving is claimed. The pack supplied overlapping evidence and named
the relevant source; reading assertions was decisive, as D5 requires.

Because no edit was proposed, there is no accepted changed suite on which to
claim a successful review → edit → full-guard loop. This slice does not satisfy
that stronger acceptance gate. Real guard pass/fail and trusted-policy rejection
are tested independently by the Action integration tests; they are not counted
as this experiment's outcomes.

Do not expand the sample until a defensible cleanup proposal exists. Ship the
pack as review evidence, without a deletion or cleanup-rate claim. The next best
action for a future cleanup demonstration is an owner-chosen maintenance change,
followed by full guard, rather than searching indefinitely for removable tests.
