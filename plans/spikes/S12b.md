# S12b — Dependency evidence for selective PR execution

Date: 2026-10-25. Status: concluded; tested Node mechanism passed, latency gate failed. The owner explicitly
requested making selective PR mode work and validating it if possible after S12.
Astra froze the contract below. S12 remains the failed coverage-only baseline.

## Boundary

Selection is possible only for an explicitly supported execution contract.
In-process probes cannot universally prove native I/O, external services,
arbitrary shared state or hostile bypass absent. No generic completeness or
universal safety claim is allowed. Experimental code stays in `s12b/` until its
actual-runtime gates pass. Existing full guard remains authoritative.

## Dependency sidecar

Version: `cupel-pr-dependencies/1`. Record:

- `runner: {name, version}` and `runtime: {name, version}`.
- `execution: {isolation, configHash, environmentPolicyHash}`. The environment is
  explicitly constructed without secrets; record policy hashes, never values.
- `files`: a map keyed by owning test file. Each value has `imports`, `reads`,
  `probes`, `directories`, `writes`, tested `capabilities`, and `unsupported`.
  The Node profile also requires `filesystemEvents` with exact aggregate
  consistency: `{channel,path,operation,origin}`. Origin is `loader`,
  `application`, or conservatively handled `unknown`.
- `global`: the same observation channels for unowned/setup/transform activity.
- `completion: {expectedFiles, finishedFiles, errors}`.

Paths are canonical repository-relative paths, observations contain no file
contents, and capability names identify specific tested channels. A missing
owner becomes global, never discarded. Record failed existence/read probes and
directory enumeration. Cached module linkage must be observed independently of
filesystem reads. Unsupported paths/descriptors/symlinks are refusal reasons.

Bind this sidecar and the ordinary full input to the exact base commit/tree,
tracked-file and test inventories, config/transforms/setup/tier policy, runtime,
dependency installation, probe implementation and execution/isolation policy.
Validate completion. Identity hashes do not establish authenticity; trusted CI
must store the baseline outside the proposed change's write scope.

## Conservative first selection

1. Refuse missing, stale, altered, incompatible or incomplete baseline bundles.
2. Always include critical files and supported new/changed test files.
3. Include owners whose coverage, setup, import graph or observed file inputs
   depend on changed existing production files.
4. On any code change, include **all application-level non-module filesystem
   observers**, even when their recorded exact path is different. This is the
   initial policy; fine-grained read-path narrowing is deferred.
5. Global dependency scope includes all affected files. Union across runners.
6. Non-code changes take D16's explicit full-suite route, with a stated reason.
7. New/deleted/renamed source, unknown inputs, unsupported isolation or incomplete
   capabilities refuse. Do not silently substitute a full run.
8. Observe selected head execution. New unsupported channels/shared writes refuse
   acceptance even if every selected test passes. Never fill skipped rows with
   old passing statuses or feed a partial head to whole-suite guard.

## Capability and safety gates

Actual node:test, Vitest, Jest and pytest controls must cover the original source
pin beside unrelated executable coverage; cached constants/imports; sync/async,
alias, stream and descriptor reads; negative probes/listings; setup/transforms;
concurrent ownership; mocks; unsupported native/child/worker channels; shared
writes/state; missing/truncated sidecars and stale identity. All four original
S12 counterexamples remain mandatory.

Preserve normal runner isolation. A per-file-process probe lane is a named new
execution policy, not ordinary pytest semantics; compare its full oracle against
the ordinary project run and refuse unsupported shared-state assumptions.

Then execute the original 15 cases per runner plus dependency controls, a
cross-runner case and clean/unsupported cases. Require zero false greens and
exact decisions. Distinguish selected-and-caught, full-and-caught and refusal.
All-refusal is safe but not useful. Allow one bounded repair round for observed
failures; further dependency classes return to Astra for a scoped decision.

After synthetic acceptance, test two eligible real scratch changes per runner.
Measure three alternating paired warm runs. Separate baseline capture,
instrumentation, selection/setup, selected execution, changed-critical mutation
and ordinary full wall time. Useful savings on at least two actual workloads
are required before promotion; selected shares are not speed measurements.

## Results

Initial capability round: JS observed the source-text and several standard I/O
channels, but left descriptors/boundaries/module linkage unproven. Python's
path graph caught seven of eight actual fault cases; arbitrary shared in-memory
state produced another false green, and changing to per-file processes broke

The strict orchestrator replay ran 60 ordinary full oracles, detecting 40 faults,
with 60 refusals and no selective execution. This is not a passing safety or
usefulness gate. Its evidence/selector tests passed 12 cases on the tested Node

## Authorized bounded repair: Node only

The owner explicitly approved validating Node-only first. Astra froze
`node-readonly-files-v1`: exact Node 22.23.3 / 26.7.0; ordinary per-file process
isolation; native module loading; read-only repository inputs; explicitly owned
private temporary output. The initial scope admitted only local JavaScript.
After concrete lane eligibility checks, Astra explicitly added locally installed,
lock-bound pure-JS dependencies and native erasable `.ts`/`.mts`/`.cts` loading.
No package installation runs inside the profile, no JSX/TSX or custom transforms
are supported, and no alternate compiler is selected. Reject
child/worker/addon/WASI/custom-loader/VM/network
channels, unknown descriptors, symlinks and external inputs. A persistent denial
must make the trace unacceptable even when the test catches the exception.

Use synchronous `module.registerHooks` and a constrained child permission model,
not a loader worker or a changed shared-process test lane. Preserve input hashes
and per-file ordinary/constrained result parity. Track native-loader dependencies
separately from top-level application reads; never suppress a broad loading
interval. Run all required positive/negative controls on both exact runtimes.
This is a cooperative execution profile, not an adversarial sandbox claim.

Installed package names alone are insufficient: bind the local lock, actual
observed transitive JS/JSON files and package metadata bytes, module conditions
and runtime. Changed dependency bytes or installation/lock identity refuse.
Native TS controls require ordinary/constrained parity, cached import linkage,
raw-source hashes, unsupported-syntax refusal and a caught executable TS fault
on both tested runtimes. The real Express lane uses Node 26 only, respecting
its existing Node >=24.15 requirement.

The engine's clock ban is not a ban on all target tests. This particular
cooperative feedback profile additionally refuses observed nondeterministic
target APIs through named, tested persistent denials, while retaining private
instrumentation timers. Do not claim control over every imaginable API or
arbitrary races. Full guard remains authoritative.

After capability acceptance, rerun the original Node matrix with at least one
strict subset and the source-pin fault caught. Then keep a real lane's entire
existing inventory/config, test two real changes and three alternating full/
selected timing pairs. Refused real lanes may not be silently narrowed. No
savings or an all-refusal outcome means usefulness remains unproven and this
repair stops. Only a passing result may progress to an opt-in production API.
Jest/Vitest/pytest selective and mixed-runner modes stay explicitly unsupported;
their existing collectors and full guard are unaffected.

Capability observations and raw outputs stay under `.scratch/s12b/`;
reproducible source and tests remain under this spike directory.

### Approved opaque-input implementation contract

Astra planned the following bounded extension after the owner's approval:

- Explicit `inputPolicy`: `strict-v1` remains the default; the only additional
  value is `express-root-npmrc-opaque-v1`. Never infer permission from a path or
  sidecar, and never accept arbitrary excluded paths.
- Only exact root `.npmrc` is opaque. Metadata-only preflight permits absent or
  regular with one hardlink; symlink, directory, special-file and multiple-link
  cases refuse before any content reads. Nested `.npmrc` and every other private
  path keep strict refusal. No content hash, size, timestamp or inode is stored.
- Bind policy and absent/regular descriptor into configuration and environment
  identities; use the same explicit policy in baseline, head and post-run checks.
- Deny test access before reads, writes, probes, descriptors, streams or loader
  operations, including aliases and missing-path probes. Deny parent enumeration.
  Caught denials persist. Trusted metadata checks identify aliases without opening
  contents; the cooperative profile is not an adversarial sandbox claim.
- A privacy-only preload protects the full reference run too, preserving its
  complete inventory and normal Node file isolation. Denials invalidate the
  reference even if caught by a passing test. Report **privacy-guarded full**
  timings, with the privacy guard cost included.
- Test preflight with zero content reads/hashes, all relevant access families,
  hardlink/symlink aliases, policy mismatch and persistent denials on both exact
  Node versions. Freeze a new runtime identity and rerun the original matrix
  before the unchanged Express lane and both real fault/timing cases.

Astra's predeclared usefulness gate required both faults to retain exact
failures, select strict subsets, be faster in at least four of five pairs and
save a median of at least 10 ms. **It failed.** Astra reviewed the final evidence
and confirmed stopping performance work on this workload. No manufactured
heavier fixture, indefinite repository search or further optimization follows
from this pass.

Production CLI/MCP promotion remains blocked. Node-only selective feedback is
feasible in this tested cooperative profile, but it does not reduce latency on
this real lane. The spike is concluded without promotion. Existing full guard remains authoritative; Jest, Vitest,
pytest and mixed-runner selective modes remain unsupported.
