# S14 — Do the installed artifacts work outside this checkout?

Date: 2026-10-25. Status: artifact and bounded documentation-consumer slices
passed; hosted Action acceptance remains unverified.

## Method

`node --test scripts/package-smoke.test.mjs` builds the actual private npm tarball,
installs it into a clean scratch prefix offline, and invokes its installed binary.
It builds the Python wheel using the pinned setuptools 80.9.0 backend and installs
the wheel plus pytest into a clean virtual environment offline. Neither test
imports the collector from its source tree. No publishing command runs.

The host's setuptools 84.0.0 and pytest/pluggy installation could not satisfy this
gate. The initial Python test recorded an explicit blocker. A separate isolated
tool environment was then prepared with the exact build/test versions recorded
in `plans/DECISIONS.md`; it did not alter the host installation or change the
backend. The build and install tests themselves make no network calls.

## Findings and repairs

- The initial npm tarball lacked LICENSE and NOTICE. Both are now package-local
  copies, included explicitly and checked against the canonical root files.
- The Python wheel now includes the same legal files, checked inside the real
  wheel. Its private upload-prohibition classifier remains present.
- Python metadata advertised 3.10+ even though the collector already rejects
  Python before 3.12. Metadata now states 3.12+; no alternate collector was added.
- The initial Python smoke used system packages and could leave collection
  unverified. It now uses a clean venv, verifies the installed import location,
  and requires successful collection of all five conformance-fixture rows.
