# S30: per-test coverage of Worker code in workerd (2026-11-23)

**Question.** Can Cupel measure, per test, which lines of Worker code ran inside
workerd, with the project's tests, harness and files unchanged?

**Verdict: yes, with an exact-but-slow method.** Recorded with D18.

## Finding 1: V8 precise coverage cannot start in workerd

workerd's inspector parses every DevTools command first
(`src/workerd/io/worker.c++`, `dispatchProtocolMessage`, and `src/workerd/io/cdp.capnp`).
It keeps `Profiler.enable`, `Profiler.start`, `Profiler.stop` and
`Profiler.setSamplingInterval` for its own CPU profiler and never forwards them to
V8, so `Profiler.startPreciseCoverage` answers "Profiler is not enabled". Every
other command, including all `Debugger.*` and `Runtime.*`, goes to V8 unchanged.
A duplicated `method` key does not get past the parser: workerd and V8 read it
the same way, in either order. Cupel does not rely on parser quirks.

## Method: never-pausing breakpoints, rebuilt into V8 block coverage

1. Cupel's node:test preload sees the test start workerd (Miniflare, wrangler and
   the workerd package all run `workerd serve`). It adds
   `--inspector-addr=127.0.0.1:<free port>` to that one command line.
2. It holds workerd's control pipe (fd 3, where workerd says it is ready) until it
   has connected, so no request the test sends is missed.
3. For each script that is byte-for-byte a repository file (Miniflare appends one
   `//# sourceURL=` line, which is allowed; bundled or transformed scripts are
   left out and counted), it sets a conditional breakpoint at every location V8
   can stop at. The condition records the location and returns false, so nothing
   ever pauses.
4. Every 100 ms hits are drained with `Runtime.evaluate` and their breakpoints
   removed. At each test boundary, and just before the harness kills workerd,
   hits become intervals and the removed breakpoints are restored.
5. `workerd-ranges.mjs` rebuilds V8-style block coverage from hits: a hit covers
   up to the next stop of its function, skipping nested functions and ternary
   branches that did not run, stopping at `else`/`case`/`catch`/`finally`, at
   block openings and after explicit jumps; a block's closing brace runs when its
   last statement starts; a switch's when the switch runs; entering a function
   covers its header and closing brace. Module top-level code runs at startup,
   before breakpoints exist, and is counted when the script loaded, which is how
   Cupel already treats module loading in Node.

## Equivalence with V8

Both methods run in Node (same V8) over Cupel's own engine, driven by its
conformance cases (`test/workerd-ranges.test.mjs`):

| Cases | V8 lines | Rebuilt equal | Only V8 | Only rebuilt |
| ---: | ---: | ---: | ---: | ---: |
| 24 (the permanent test) | 965 | 965 | 0 | 0 |
| 60 | 1,270 | 1,265 | 4 | 1 |
| 95 (an earlier rule set) | 1,369 | 1,369 | 0 | 0 |

The remaining 60-case differences are a closing brace of a `case 'x': { ... }`
block (two lines), one multi-line nested ternary (one line each way) and one
loop's closing brace. They are listed so that a later change can close them.

## Real project: a private Workers codebase (Miniflare 5, Durable Objects)

- One test file, 17 tests, 15 Worker modules (1,522 lines): all 17 tests pass
  under Cupel exactly as without it; 1,237 lines are attributed to tests.
- Fixture (`spec/conformance/adapters/workerd`): each of two tests gets exactly
  the lines of the function it reaches; two runs agree; no file changes.

## Cost

Functions holding breakpoints run unoptimised. Plain: 13 s for the 17-test file;
with coverage: 3.6 min, almost all in one fuzz test that sends thousands of
requests (150 s against 7 s). Light tests cost about 0.6 s each for attaching.
Use changed-test selection for per-change runs and full collection nightly.

## Not covered

- Code compiled to Wasm (Rust compiled to a `.wasm` module): V8 reports no Wasm lines. Phase 7
  labels such crates as run by the tests that loaded the module.
- Tests that run inside workerd themselves (`@cloudflare/vitest-pool-workers`):
  not attempted in this spike.
