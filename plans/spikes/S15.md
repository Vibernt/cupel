# S15 — Jest 30.2.0 capability and adapter spike

## Method

Installed Jest 30.2.0 in ignored `.scratch/jest-runtime` and later in the
test-only conformance fixture. The offline npm cache held version metadata but
not `concat-map-0.0.1.tgz`, so the offline install failed `ENOTCACHED`;
test-setup installation then used npm normally. No product dependency was
added. Ran a custom `jest-environment-node` subclass with `node:inspector`
`Session.connect()` to take precise-coverage snapshots at circus boundaries.
Queried `Debugger.getScriptSource` for original and transformed scripts, used
inline source maps for TypeScript, selected duplicate-name tests by changing
their mode at `test_start`, and injected mutants into the project's transformer
input with Jest's disk cache off. The conformance fixture includes setup hooks,
two parameterized rows, two equal names, two concurrent cases, a TypeScript
source and a source-text pin.

## Measurements

| Check | Observed result |
| --- | --- |
| Baseline fixture | 8 of 8 tests passed in each of two runs; first run about 0.8 s |
| Exact recheck | Parameterized unit: 2 passed, 4 skipped; second duplicate: 1 passed, 5 skipped |
| Concurrency | Both concurrent tests received the same overlapping `src/math.cjs` line set (`1-6`) |
| TypeScript map | Original `src/typed.ts` coverable `1-4`; behavior test covered `1-4`; setup `1,4` |
| In-memory mutation | 2 of 2 sampled TypeScript mutants killed by behavior test; source-text pin passed and was not a killer |
| CLI mutation | 1 of 1 critical-source mutant killed; source SHA-256 unchanged |
| Initial actual-runtime tests | 15 of 15 passed on Node 26.7.0 and 15 of 15 on Node 22.23.3, including skipped-then-passed K13 aggregation, missing-hook/map and unsupported environment negatives |

Jest's package version was 30.2.0; its `--showConfig` output reported
`version: 30.1.3`, so the adapter validates installed package versions and
resolved circus/environment modules rather than assuming that config field is
the package version.

## Verdict

The narrow capability pilot passed, and the collector and mutator work on the
repository conformance fixture. Unsupported combinations are rejected explicitly. This is
not yet a real-repository acceptance run. Full repository verification,
native ESM, other Jest versions, helper-based parameterized registration,
custom environments, and external source-map files were not verified in this
initial spike.

## Private installed Git-guard acceptance

The final private handoff exercised the actual installed CLI with a candidate-owned
Jest Git repository and mutation enabled. This exposed an eager asynchronous
configuration probe in zero-mutant sessions: base extraction cleanup could delete
the child's working directory before Jest startup, producing `uv_cwd ENOENT`.
The runner now creates and awaits the cached config promise only when a valid
mutant needs it. A real zero-mutant `guard --base HEAD` regression passes.

The Jest runtime file now has **16 passing tests** under each exact Node runtime,
and both required full gates pass. In the stable installed critical-source fixture,
all **3/3 mutants were killed** at baseline; unchanged Git guard passed. A weakened
critical assertion still passed Jest but lost all three kills, and full guard
returned **exit 1** with critical-mutation and coverage loss. No saved-input or
`--no-mutation` alternate route was used for these Git guard checks.
