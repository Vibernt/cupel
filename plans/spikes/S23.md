## Interface and identities

New profile: `node-readonly-files-v2`. New baseline: `cupel-pr-baseline/1`.
New scoped result: `cupel-pr-result/1`; never an ordinary whole-suite report.

CLI, with corresponding strict MCP tools `cupel_pr_prepare` / `cupel_pr`:

```
cupel pr-prepare --profile node-readonly-files-v2 --base EXACT_COMMIT \
  --producer-sha256 TRUSTED_PIN --out ARTIFACT
cupel pr --profile node-readonly-files-v2 --baseline ARTIFACT \
  --baseline-sha256 TRUSTED_PIN --base EXACT_COMMIT \
  --producer-sha256 TRUSTED_PIN --out RESULT
```

Coordinator functions accept only those explicit identities plus root/runtime
and private output paths. Independently trusted expected pins are mandatory;
no caller-provided validated context, baseline recapture, artifact upgrade or
hidden execution route. S18 artifacts are incompatible because they lack the
new profile's collection and critical mutation evidence.

Keep host modules small under `packages/cupel/src/pr/`: artifact, identity,
prepare, request, selection, assessment, and `profiles/node/` launcher,
collection, loader, tracing and mutation transport. Add a dedicated result
schema without changing the pure engine's ordinary input/report semantics.

and matching index/tree. Output stays outside it; dependencies are already

## Trusted mutation transport

The current profile denies registering loaders after bootstrap. Do not layer
ordinary `mutateNode` hooks after lockdown or remove that denial.

Install one trusted resolver/load hook before lockdown. Receive a host-validated
frozen mutation specification through a private startup pipe, binding exact
source URL, original raw digest, descriptor and replacement digest. Store
replacement text in a private closure and serve it only through module loading.
Filesystem source reads remain original. Emit loaded proof, then deny further
custom loaders. Mutation and all retries, timeout probes and confirmations run
under the identical profile and fresh identity/trace checks. Unsupported activity
invalidates the attempt and can never count as a kill.

## HEAD request and D16

1. Read/hash/validate sealed history once against independent pins.
2. Capture fresh HEAD inventory/config/dependencies/producer evidence.
3. Select critical files, new/changed tests, coverage/dependency owners and
   conservative filesystem observers. Refuse unknown unsupported dependencies.
4. Execute and collect selected statuses, coverage and traces.
5. Validate critical identities/tags. Removed/renamed critical tests refuse;
   edited critical tests require fresh identity evidence.
6. Derive changed critical HEAD lines from verified content differences and
   critical policy. Mutate only that scope using current selected-file evidence.
7. Compare compatible baseline mutant identities and confirm required survivors
   twice. New/noncomparable sites stay explicitly separate; absent baseline
   identity never implies improvement.
8. Recheck HEAD/producer/dependency identities before accepting scoped results.

Budget exhaustion or missing required mutation/confirmation produces incomplete
evidence, not success. Non-code changes use the declared **profile-full** route,
with reason. Unsupported changed configuration refuses; never switch to ordinary
runner semantics. Do not invoke ordinary whole-suite guard with partial HEAD or
fill unexecuted rows from historical passing statuses.

## Result and exits

Return profile and baseline/HEAD identities, route/reason, executed/unexecuted
files, exact comparison scope, tests, mutation/completeness and refusals, plus
separate preparation/execution costs. No field claims a whole-suite pass from
selection.

- 0: all required work in the declared PR scope completed without failure.
- 1: executed tests failed or compatible scoped protection regressed.
- 2: invalid invocation.
- 3: unsupported/refused/stale/incomplete evidence.

New survivors remain visible evidence; do not invent a new mutation threshold.
Whole-suite protection approval still uses ordinary full `guard`.
