# S27 — isolated Jest compiler bridge and native resolver blocker

Date: 2026-10-25. Status: scratch implementation and targeted controls complete;
actual Jest clean execution and selective capability **blocked**. No product
source, schema, dependency manifest, existing Node profile, or published
capability changed.

## Contract and method

The owner authorized separately named opt-in isolated profiles, retaining exact
per-test coverage and refusing unsupported suites. This slice attempted
`jest-30.2.0-cjs-node26-isolated-files-v1`: exact Node 26.7.0, Jest 30.2.0,
standard Node environment, one project, explicit in-band file isolation,
CommonJS `.cjs`/`.js`, and no project transforms, ESM, custom environments,
arbitrary Jest configuration, mocks or fake timers. This is provisional code,
not an accepted profile. Node 22 selective execution refuses explicitly before
creating an attempt directory or executing subject code.

During the Node profile's source freeze, all proposed implementation and tests
were written under ignored `.scratch/jest-profile-development/`. The mirror
contains `packages/cupel/src/pr/profiles/jest/{attempt.mjs,launch.cjs,
compiler.cjs,guard.cjs,policy.cjs,coverage.cjs,environment.cjs}` and frozen local
copies of the existing proven filesystem/descriptors/privacy/provenance
helpers. It imports no mutable production Node profile at child runtime.
Tests are `tests/bridge.test.mjs`, `tests/compiler.test.mjs` and their trusted
test-only `compiler-probe.cjs` harness. No dependencies were downloaded.
The installed `spec/conformance/adapters/jest/node_modules` tree was used
read-only. Installed `.bin` symlinks are bound as metadata and never executed;
subject source symlinks refuse.

The host starts a child with Node's permission policy, inspector permission
and disabled SIGUSR1, declared filesystem read roots, private output writes,
and no child/worker/addon grants. A private stdin record supplies declared
source pins and mutation transport. Project configuration is not evaluated:
only declared CJS setup paths are accepted; the trusted launcher constructs the
finite configuration and installs guards before calling Jest's `runCLI`.

The compiler bridge records raw SHA-256, original path, importer, transformed
SHA-256 and `sourceMap:null` for the no-transform CJS contract. Records live in
private WeakMaps and are consumed once. Compilation rechecks original bytes
and invokes a captured native `vm.compileFunction` directly; subject VM APIs
receive no grant. A private mutation replacement changes only compiled text,
retains pristine filesystem reads, and emits loaded proof binding both hashes.
The compiler unit harness exercises actual VM bytecode, not a mocked compiler.

## Concrete blocker

Jest's default resolver is native in this installed dependency tree.
`jest-resolve/build/index.js` lines 168–199 creates an
`unrs-resolver.ResolverFactory`; `unrs-resolver` version 1.12.2 loads its
platform `.node` binding. The proposed profile denies `process.dlopen` and has
no Node addon permission. The actual clean attempt retains three `native-addon`
denials and ends with a Jest configuration error resolving
`jest-circus/build/runner.js`. It records **zero subject compiler records** and
**zero completed runner records**.

The installed `unrs-resolver/index.js` contains optional WASI loading after a
failed native load. These attempts did not create successful runner evidence;
all denials remain fatal to profile acceptance. No WASI flag, native grant,
alternative resolver, installation or automatic fallback was introduced.
Native resolver filesystem reads would bypass JavaScript filesystem hooks;
merely allowing the addon would not establish dependency completeness.

## Verdict and next action

The authenticated compiler and pristine-source mutation primitives have positive
and negative runtime evidence. Jest selective execution is still unsupported.
The next decision is whether to authorize a **separately named pure-JavaScript
resolver contract**, with ordinary/profile eligibility parity and its own resolver
negative cases, or retain the explicit native-resolver blocker. That decision
was referred to the owner; no dependent implementation was started.

Not verified: the proposed custom environment/VM constructor handoff in a
successful real Jest run; inspector/circus coverage completion, setup/teardown
and overlapping concurrent attribution; config/setup/module resolution
observation completeness; actual framework source-pin mutation; whole ordinary
versus profile parity; strict selected subsets; S12 faults; selection/artifact
integration; mutation kills/survivor confirmation; latency/RSS measurement;
real-repository acceptance; installed CLI/MCP acceptance. No all-refusal result
or isolated bridge unit test substitutes for these remaining gates.
