try its default Node resolution. Two exact synthetic bootstrap requests map to
the fixed environment and sequencer paths. There is no stack-based resolver

## Concrete remaining blockers

1. The guarded actual run no longer reaches the unrs native resolver. It
   retains a fatal native denial for `fsevents/fsevents.node`, followed by the
   existing descriptor-write denial for haste-map's private cache. There are
   still **zero subject compiler records and zero runner completion records**.
   Installed `jest-haste-map` 30.1.0 eagerly imports its FSEvents watcher at
   `build/index.js:2273`; that module unconditionally tries `require('fsevents')`
   inside a catch at lines 1073–1078 even with watching disabled. Its
   `forceNodeFilesystemAPI` option only controls crawling and does not prevent
   the eager native attempt. No native grant, fake watcher module, patched
   installed source, WASI route or optional-module recovery was introduced.
2. Independently, S27's scratch policy and guard infer subject trust from a
   mutable `Error.stack`. Actual authenticated VM code recovers host `Error`
   via `Object.getPrototypeOf(require('assert').AssertionError)`, replaces
   `prepareStackTrace`, and reads a synthetic private control marker with
   **zero unsupported events**. The new test named `UNSAFE DIAGNOSTIC` preserves
   this reproducible counterexample. Passing compiler controls cannot establish
   isolation while that private-control bypass exists.
