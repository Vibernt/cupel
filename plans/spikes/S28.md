# S28: Python metadata-interception boundary probe

Owner-authorized slice: **test the metadata boundary; stop if incomplete**.
This is a separately named, scratch-only `python-metadata-interception-probe-v1`
experiment. It does not implement or accept `pytest-readonly-files-v1`, and it
adds no selective runner, CLI/MCP capability, package dependency or fallback.

## Decision-complete method

1. Use only the existing `.scratch/package-tools/runtime/bin/python3.14`
   interpreter, asserting Python **3.14.8**; the installed pytest is **9.1.1**.
   No interpreter substitution, installation or network access is required.
2. In `.scratch/python-metadata-boundary/`, install wrappers before experimental
   subject operations, retaining the audit hook for file opens, directory reads,
   process/network/native-import denials. Persist denials when subject code
   catches their exceptions. Exercise both `os` and `posix` aliases, importlib
   cached aliases, capability sets, descriptors and directory-entry methods.
3. Compare real missing-file operations before and after the host creates a
   synthetic file. Verify positive content reads, directory reads, ordinary
   metadata, `dir_fd`, `follow_symlinks` and owned/unowned descriptors.
4. Independently attack pre-bootstrap cached native references and native
   references available to ordinary subject code after bootstrap. A passing
   reproducer of an unobserved operation **fails completeness**. Stop promotion
   when that happens; do not proceed to collector parity or selection claims.

The scratch implementation has four small files: `boundary.py`, `directory.py`,
`probe.py` and `test_boundary.py`. Each operation runs in a fresh child process.
Only synthetic temporary fixture files are read or written. The audit denial
for a network channel is tested by explicitly emitting `socket.connect` via
`sys.audit`; it makes no socket or network call and is not a real-network test.
The process denial uses an actual attempted `os.system` call, denied before
execution. Fresh native-module construction is also exercised directly.

## Numbers and passing controls

Command from the repository root:

```sh
.scratch/package-tools/runtime/bin/python3.14 -B -m pytest -q \
  .scratch/python-metadata-boundary/test_boundary.py -p no:cacheprovider
```

Final run: **34 tests passed in 2.91 s**, comprising **48 fresh probe children**.
These are 21 positive trace controls, five persistent-denial controls, and eight
incompleteness/unfinished-policy reproductions. Their passing test status means
that each expected observation or defect was reproduced; it does **not** mean
that the boundary passed acceptance. This duration is test-harness wall time,
not a collection, selective-request or performance measurement.

The seven missing-file controls are `os.stat`, `os.lstat`, `os.access`,
`posix.stat`, `Path.exists`, `Path.stat` and importlib's `_path_stat`. Each traced
the missing path before raising/returning false, then traced it and observed
presence after creation. Fourteen positive controls covered a real text read,
`listdir`, `fstat`, `stat(fd)`, relative `stat` and `access` with an owned
`dir_fd`, `follow_symlinks=False`, `DirEntry.stat/is_file/is_dir/inode`, context
manager iteration, the rewritten `os.supports_fd` alias, and `glob`.

Caught-denial controls retained refusal evidence for an unowned descriptor,
write, process, simulated network audit event, and direct native module
regeneration. Replacing the public `_imp.create_builtin` entry did deny direct
use. Direct pre-interception `_imp.create_builtin(ModuleSpec('posix', ...))`
created a distinct native module without any audit event, demonstrating why
that channel needs enforcement.

## Completeness failures

**Directly reachable after bootstrap, without artificial early subject code:**

- The wrapper's `__closure__` exposes its original native `stat` callable. An
  ordinary subject can recover and invoke it. The missing file returned false
  before creation and true after creation, with **zero trace and zero denial**
  in both executions. This is a concrete bypass of this Python wrapper design;
  it is not a proof that every possible Python enforcement design is impossible.
- The experimental directory wrapper exposes its native entry through `_raw`.
  Calling the public native descriptor `os.DirEntry.stat(entry._raw)` observed
  a synthetic file's size changing from **9 to 16 bytes** without an additional
  metadata event or denial. The preceding directory listing is observed; its
  existence does not establish a per-entry metadata trace.
- Public `posix.statvfs` remains unwrapped. Its missing-file result changes after
  creation with **zero trace and zero denial**. The narrow stat/access list does
  not cover every public native metadata entry point. This is an implementation
  omission, not a demonstrated impossibility of wrapping that individual entry.

**Artificial pre-bootstrap captures, demonstrating a separate startup obligation:**

- Native `posix.stat` retained inside a tuple, `functools.partial`, and a
  preconstructed `map` each observed missing-versus-created file changes with
  **zero trace and zero denial**. These synthetic captures model native
  references held by preloaded trusted code; they do not show that project code
  ran before the bootstrap or that these exact containers occur in pytest.
- A tuple retaining `_imp.create_builtin` and `_imp.exec_builtin` regenerated
  and initialized a native `posix` module despite replacement of the public
  entry points. Its `stat` also observed the created file with **zero trace and
  zero denial**. An initial exploratory control omitted `exec_builtin` and its
  successful stat segfaulted; that was an invalid uninitialized-module probe,
  was corrected, and is not counted as a passing control. The final reproducer
  explicitly initializes the regenerated module.

The additional `realpath` control returned its normal path while internally
catching multiple denied ancestor metadata probes. The denials remained
persistent. The scratch root-only policy therefore still needs a specified
ancestor policy before ordinary/constrained parity could be considered; this
is a policy/implementation gap, not an intrinsic `realpath` impossibility.

## Verdict and unverified work

**STOP: the metadata boundary is incomplete. No production source promoted.**
The concrete directly reachable native references defeat this experimental
wrapper boundary. Replacing a few public aliases and capability-set entries
cannot be represented as a complete dependency trace. No fallback, broader
profile, alternate interpreter or guardrail relaxation was introduced.

This slice did not run pytest config/conftest/subject under a complete enforced
profile. Custom loaders, tempfile behavior, zipimport behavior, arbitrary C-level
helper/iterator dispatch, symlink/path-identity completeness and real network
refusal were not accepted or exhaustively verified. Existing per-test
`sys.monitoring` collector parity, setup/teardown/parameter parity, critical
mutation, strict-subset selection, source pins, full-profile runtime costs,
installed CLI/MCP and real-repository acceptance were **not run**, because the
metadata completeness gate failed first. No claim is made about their results.
The existing ordinary pytest collector and full guard are unchanged by S28.

Next best action: retain the explicit Python selective-profile refusal and
review these concrete holes before authorizing any different enforcement
boundary. Further profile implementation requires a separately accepted way to
observe or refuse those channels while retaining required pytest semantics.
