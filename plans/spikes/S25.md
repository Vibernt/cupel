# S25: Rust multi-file source-graph mutation proof

## Decision and boundary

S20 proved a single-file Rust crate-root substitution only. S25 asks whether a controlled, no-dependency Cargo crate with `lib.rs -> outer.rs -> outer/inner.rs` can execute a changed **non-root** function while all original files remain byte-identical and runtime source reads, `include_str!`, `include_bytes!`, `file!`, `module_path!`, `line!`, and `column!` retain their baseline values. Rust language mutation is requested; a Rust engine port remains deferred. This is a scratch proof, not a product mutation backend or CLI capability.

## Chosen experiment

1. Create a fixed fixture with three module levels. The innermost value returns `1`; an equal-width replacement returns `2`. Baseline `cargo test --offline --locked` must pass. Capture every source file SHA-256 and macro metadata before substitution.
2. A `RUSTC_WRAPPER` substitutes Cargo's crate-root compiler argument with a scratch `lib-mutant.rs`. For each ancestor, retain its source text except a same-line `mod child;` rewrite to `#[path="child-mutant.rs"] mod child;`. Keep a pristine symlink under each original basename so relative include macros read original bytes. Put the mutated leaf in its own renamed scratch file and symlink its original basename to the pristine source. Remap each renamed scratch path to its exact original path with `--remap-path-prefix`. Do not modify any original file or test expectation.
3. Run the behavior test and all source/macro pins under Cargo with an empty scratch `CARGO_HOME`, scratch target and home, `CARGO_NET_OFFLINE=true`, and `--offline --locked`. The behavior test must fail specifically with value `2`; all pins must pass; baseline and mutant macro metadata must match exactly; all three original hashes must remain unchanged. Run the same Node smoke on installed Node 26 and Node 22.
4. Probe refusal controls for build scripts, proc macros, `include!`, `#[path]`, `cfg`, and generated/`OUT_DIR` source. These are outside the fixed graph substitution. A proof preflight will explicitly refuse each control before calling Cargo. It is a bounded proof scanner, not a production parser or an exhaustive Rust grammar recognizer.

## Decision rule

If any normal module load or macro/source-position pin differs, record the exact compiler input and failure and stop without relaxing pins, changing the original sources, or substituting a hidden fallback. If the controlled graph passes, report only that primitive. Arbitrary module declarations on the same line as `line!`/`column!`, macro-expanded modules, compiler-created paths, features/cfg, build scripts, procedural macros, dependencies, runtime I/O, and Cargo's whole source graph still require a production inventory, refusal design, and tests before Cargo mutation can be enabled. Passing this proof does not turn on Cargo in the CLI or establish selective PR execution.

## Acceptance and measurements

- Exact rustc, cargo, Node versions and offline environment; no install, download, network, external mutator, larger heap, or subset fallback.
- Fresh no-dependency fixture; one baseline full-suite pass, one mutant behavior failure with value `2`, source and macro pins pass, and original SHA-256 values before/after match.
- Six negative channels each produce an explicit refusal; smoke tests pass on Node 26 and Node 22.
- Report what Rust language mutation can be implemented next, what is blocked or infeasible under this mechanism, and a decision-complete next action. Do not claim a Rust engine port or general/selective Cargo support.

## Result (2026-10-25)

The controlled three-file graph **passed**. Exact local tools: `rustc 1.97.1 (8bab26f4f, Homebrew)`, `cargo 1.97.1 (c980f4866, Homebrew)`, host `aarch64-apple-darwin`, Node `v26.7.0` and `v22.23.3`. Every Cargo command used `--offline --locked`, `CARGO_NET_OFFLINE=true`, a fresh empty scratch `CARGO_HOME`, scratch `HOME` and `CARGO_TARGET_DIR`, and the fixed local Homebrew Cargo/rustc. The fixture has only the standard library and one local crate. No dependency install, download, network, external mutator, increased heap, or alternate test subset was used. The filtered behavior and pin runs are separate observations after a passing full baseline, so a source-pin failure cannot be credited as a mutation kill.

The full baseline ran **2/2 passed**. A scratch-only change in `src/outer/inner.rs` from `pub fn value() -> i32 { 1 }` to `pub fn value() -> i32 { 2 }` made the behavior test fail with `left: 2`. The separate pin test passed **1/1** under the mutant. Its runtime reads and relative `include_str!`/`include_bytes!` at the root, ancestor, and leaf all equaled the pristine original files. The baseline and mutant emitted these **identical** macro tuples `(file!(), module_path!(), line!(), column!())`:

| Module | Baseline and mutant tuple |
|---|---|
| root | `("src/lib.rs", "cupel_rust_graph_proof", 14, 67)` |
| outer | `("src/outer.rs", "cupel_rust_graph_proof::outer", 13, 40)` |
| inner | `("src/outer/inner.rs", "cupel_rust_graph_proof::outer::inner", 10, 40)` |

The wrapper log records Cargo passing `src/lib.rs` as the crate-root compiler argument. The wrapper replaced it with the scratch `lib-mutant.rs` and remapped the three scratch module paths to `src/lib.rs`, `src/outer.rs`, and `src/outer/inner.rs`. Each original basename in the scratch graph was a symlink to the original file, so relative inclusion read pristine bytes. The only source-text edits were in scratch: two same-line module declarations became explicit absolute `#[path]` declarations and the leaf's one-character behavior expression changed. The three original SHA-256 values were checked before and after every run:

| Original file | SHA-256 before and after |
|---|---|
| `src/lib.rs` | `8ca0d89362530b92c1cbc0a1879b1eec29e947a975807917b06afabc06344c58` |
| `src/outer.rs` | `f243c150e1752fc4a596276b04020bf24a1bbd0910bbcdd8ce40b73428deb810` |
| `src/outer/inner.rs` | `5229a148e6070e0793abcbfeece6db67ec1c8e04fa314a4efc57daacd1cae6a9` |

The six negative controls explicitly refused **build scripts, proc macros, `include!`, existing `#[path]`, `cfg`, and a generated-source symlink** before Cargo mutation. The proof scanner is deliberately fixture-scoped and is not a complete Rust parser. Other generated-source spellings and macro expansions remain unproven. `node --test plans/spikes/s25-rust-graph/graph.test.mjs` passed **2/2** on Node 26.7.0 and **2/2** on Node 22.23.3.

## Verdict and next action

This demonstrates a **bounded Rust language mutation primitive** for a plain nested module graph with isolated declaration lines and fixed source positions. It can support a future restricted backend after a complete graph inventory, deterministic site IDs, production-grade source/channel refusal, full-suite baseline equivalence, source/test freshness, invalid-compile classification, survivor confirmation, packaging, conformance tests, and a real-repository run. The current `#[path]` rewrite lengthens ancestor declarations; if a line or column macro shares one of those lines, source positions can change. The proof does not authorize rewriting such modules, and it does not prove a general substitute for rustc's missing source overlay channel. Build scripts, proc macros, `include!`, pre-existing `#[path]`, `cfg`, generated source, dependencies, and runtime source/native I/O have no safe mutation mechanism verified here. Rust/Cargo remains refused in the product CLI. Rust selective PR execution is unproven, and the Rust **engine port** remains deferred.

Next best action: design a restricted Rust language profile that rejects every unmodeled source graph and source-position case, then implement it only after the owner accepts that bounded scope. A general Rust profile needs a separate compiler-input solution for arbitrary module/macro graphs; this spike found none. Do not enable Cargo mutation based on this fixture alone.

## Restricted production backend implementation (2026-10-25)

After the owner accepted a bounded Rust language profile, the implementation moved from the ignored development mirror to `packages/cupel/src/mutate-rust/`. This is an actual internal mutation/confirmation backend with modular lexical grammar, inventory, graph materialization, site generation, wrapper, process, result, scope and orchestration files. `mutateRust` and `confirmRust` use the Go backend's input/config/scope and mutation-result conventions. A Rust engine port remains deferred.

The profile admits one ordinary standard-library-only library crate at `src/lib.rs`, Cargo edition 2021/2024, at most 64 ASCII Rust source files, bounded functions/tokens/grammar depth, and a complete ordinary module graph. External module declarations must occupy isolated lines; unknown grammar and compiler channels refuse. The parser recognizes an enumerated grammar rather than trusting the S25 proof scanner. It explicitly rejects dependencies/workspaces, Cargo configuration/custom compiler environment, build scripts, cfg/features, generated or orphan sources, pre-existing path attributes, custom/procedural macros, `include!`, doctests, raw strings, unmodeled types/traits/generics/async/control flow, unsafe paths and missing graph hashes. See `docs/rust.md` for the exact supported vocabulary and refusal limits.

Only the fixed local Homebrew Cargo/Rust **1.97.1** on `aarch64-apple-darwin` is accepted; rustc commit `8bab26f4f68e0e26f0bb7960be334d5b520ea452` and the Cargo build identity are checked. Fresh scratch HOME/CARGO_HOME/target directories, `--offline --locked`, explicit local compiler paths and a minimal child environment prevent a toolchain/dependency-resolution substitution. No dependency or toolchain was downloaded. Custom Cargo runner semantics refuse at both the direct backend and CLI capability boundaries.

All graph files require canonical raw input hashes. The Cargo collector now validates every candidate's filename/type metadata before its first source-content read, retains the inspected source bytes for test-definition scanning, and emits raw hashes for every safely inventoried Rust file. A module-only or test-only file without LLVM executable regions receives `coverable: ""`; no line or test coverage is invented. Mutation rechecks source/test/manifest/lock bytes and path identity before and after every child. Missing graph hashes, changed source/test bytes and unsafe private/symlink paths refuse; static late-listed private/symlink controls measured zero source-content reads.

The native read contract is deliberately narrow. Direct `std::fs::read`/`read_to_string` calls must name an existing pinned graph source using a literal `"src/path.rs"` or `concat!(env!("CARGO_MANIFEST_DIR"), "/src/path.rs")`. External, computed, missing and first-class aliased readers refuse before Cargo. Only `env!("CARGO_MANIFEST_DIR")` is admitted; runtime environment accessors and other environment macros refuse, including access to `RUSTC_WRAPPER` or the wrapper-spec path. This prevents accepted tests from observing the intentional compiler-wrapper environment difference. It is a source-language restriction, not an OS sandbox or arbitrary native-I/O containment claim.

Mutation writes equal-width comparison/logical/arithmetic operator replacements only in scratch. Each graph module has a renamed scratch compiler file and a pristine original-basename symlink. Ancestor rewrites retain the original line count and occupy isolated declaration lines. The wrapper records and the host checks the exact compiler argv, crate-root substitution and every remap, including a real test-harness compile. Full ordinary `cargo test --offline --locked -- --test-threads=1` establishes exact ID/status parity with input before any mutation. This is the complete **serial suite** baseline; parity with Cargo's default parallel scheduling is not claimed.

A kill requires a complete harness result and an actual failure of an input/baseline-passing test. Crashes, missing/unknown terminals, compiler/tool failures and timeouts cannot create credited killers. A compile-invalid mutant is excluded only after an unmutated compile succeeds and the trusted compiler emits target-source primary diagnostics with a Rust error code. Signal/timeout/unrelated/no-code/infrastructure diagnostics do not qualify. Every survivor receives two additional executions; historical confirmation regenerates the pinned site and executes twice more. Caps and seeded selection are deterministic; incomplete units do not enter `targeted`. Empty changed ranges select nothing, while malformed ranges, nonpositive/noninteger arrays and unknown changed paths explicitly refuse.

The controlled nested fixture produced **one reported behavior kill**, **one executed arithmetic survivor**, and **one uncovered site** reported as `no-coverage`. Initial mutation used **11 child commands**; the survivor passed both internal repetitions and both historical repetitions. At root, ancestor and leaf, the pin test asserted runtime original-source reads, pristine include bytes and exact original `file!`, `module_path!`, `line!` and `column!` values. It was never credited as a killer, and original source hashes remained identical. A separate actual String `+` to `-` mutant failed type checking and was excluded after a good compile probe. Other tests exercised stale production/test bytes, private paths, late symlinks, graph incompleteness, grammar/macros/environment/config refusals, native-read targets, deterministic caps/targeted completeness, and inherited descendant timeout termination. `npm run check` passed.

The root agent's separately executed Cargo CLI integration smoke reported **one actual kill and one guard loss**, with the source pin never killed; its native capability preflight gate passed **6/6**. Root owns the final installed artifact/MCP/full-suite gates and their results. These controlled fixtures do **not** establish a real-Rust-repository acceptance result, general Rust language coverage, native selective execution, arbitrary filesystem/process containment, default-parallel-suite equivalence, or a performance improvement. Real Rust repository acceptance remains **unrun**.

Next best action: complete root's private installed-artifact and full verification gates, then run an eligible real Rust repository through the exact admitted serial profile. An unsupported construct needs an explicit owner decision about expanding this grammar; no alternate runner, smaller inventory, dependency download or hidden fallback substitutes for a failed gate.
