# S19: measure repeated mutation coverage selection

Status: completed diagnostic, 2026-10-25. The measured gate did not pass; product code is unchanged.

## Decision

Measure `Session.select` in complete mutation and confirmation requests before
building a coverage index. A product implementation is eligible only if the
same real complete workload has both (1) at least 10 ms of selection time and
(2) selection at least 5% of its paired uninstrumented whole-request wall time.
It must also have an optimistic repeated-coverage-parse saving ceiling that
crosses both thresholds. If every complete workload misses either gate, stop
with no product edit. If a gate passes, report raw evidence for Astra's review
before implementing the already authorized bounded change. The 65-row replay cannot promote a
product change by itself.

## Instrumentation and interpretation

The checked scratch transform counts `Session.select` calls and inclusive
nanoseconds, `parseLines` calls and inclusive parse nanoseconds inside select,
first-seen versus repeated coverage strings, examined test/setup/by-file rows,
selected tests/files and targeted full-run decisions. Keep separate mutation
and confirmation counters; reset before each phase. Use `process.hrtime.bigint`
only in the diagnostic copy. Verify the transform's exact source anchors and
parse-site count, with no fallback when source shape differs. Calibrate clock
overhead and rerun with an outer-only timer if overhead might change the gate.
The optimistic saving ceiling is repeated-parse time; the proposed cache
cannot remove first parses, file/test row scans or fresh runner work.

Tests must reject a wrong source pin, changed transform anchors and counter
state leaked across phases, and prove exact selector/output parity. Store raw
results and scripts in `plans/spikes/s19/` with ignored captures in
`.scratch/s19/`. Label the synthetic source-heavy complete request separately
from existing runner fixtures. Report failures and unrun branches. If the gate fails, the
next action is no product change; if it passes, obtain Astra's review of a
bounded immutable per-session coverage index and its invalidation tests before
editing `packages/cupel/src/mutate/**`. Rust remains deferred unless a later
whole-call profile justifies its setup, copying and distribution costs.

## Result

All six complete workload/runtime combinations missed both the 10 ms and 5%
selection gates. The largest inclusive selection median was 0.579 ms; the
highest whole-call share was 0.094%. The 200-query saved Express input replay took more
than 10 ms, but had no whole-call denominator or test execution and did not
promote a cache. Exact raw paths, launch parity, tests and limitations are in
[s19/RESULTS.md](s19/RESULTS.md). Next best action: leave selection unchanged
and use the accepted private candidate. Reopen this only with a materially
different whole-call profile from an actual slow job; no further profiling
round is scheduled from these measurements.
