# S10: Do assertion-aware signals find tests to clean up, or real gaps?

## Question
S6, S8 and S6b showed that coverage and code mutation can't tell a redundant test from one with unique assertions. S10 tried two signals that look at assertions and checking directly ([s10/README.md](s10/README.md) has the definitions):
- **S10b, assertion fingerprints:** each executed assertion is recorded as (matcher, normalised subject, expected-value fingerprint). A test is *subsumed* when every fingerprint it makes is also made by another test.
- **S10a, extreme mutation:** a function's whole body is replaced with a trivial one. A covered function is *pseudo-tested* when no test fails under any such replacement.

## Data
Vibernt Assay snapshot 5a5a1313 (`tests/*.test.mjs`): 4,727 tests in 4,298 units.
- **Assertions:** recording took 84 s wall, against about 74 s for collection alone.
- **Pseudo:** function-scope mutation, capped at 600 mutants and 1,800 s, reached 580 of 8,685 functions in 26 minutes.

Two Codex judges (`gpt-6-astra` and `gpt-6-sol`) each read every finding independently ([results/](s10/results/)).

## Results

| Signal | Findings | Both judges agree it holds | Agreement |
|---|---|---|---|
| Subsumed by assertions (cleanup) | 43 tests (plus 2 clones among them) | **0** redundant (one judge said redundant on 1, the other debatable) | 42 / 43 |
| Assertion-free tests | 0 | — | — |
| Pseudo-tested functions (gap) | 29 of 580 functions checked | **28 unchecked** (the other: one judge said checked elsewhere) | 28 / 29 |
| Pseudo-tests (tests covering only pseudo-tested functions) | 0 | — | — |

**Why subsumption failed.** Tests made the same assertions in **different scenarios**: a 90-second token against a normal one, a production origin against a local one, a service that keeps refusing. The fingerprint captures *what* is checked, not the *inputs* that produced it. Redundancy needs both.

**Why extreme mutation works.** "Delete the whole body and nothing fails" is unambiguous. The pseudo-tested functions were mostly UI rendering and event handlers (`connectedCallback`, `onClick`, `draw`, `renderEvidence`) that tests drive without checking the result.

## Verdict
- **Cleanup by assertion subsumption: no.** This is the fourth negative result for automated test removal (after S6, S8 and S6b). D5 stands.
- **Pseudo-tested functions: yes, as a gap-finder.** Two judges confirmed 28 of 29 (about 97 %). This is the strongest precision of any Cupel signal so far. It belongs next to mutation gaps in `report`: "these functions run in tests, but nothing checks what they do".

## Next
- Add pseudo-tested functions to the spec as an optional input signal and a report section, not advice.
- Cost: one or two mutants per function. Default to critical and changed functions, like mutation.
- A possible follow-up for cleanup: fingerprint the inputs to the code under test too, but only if the owner wants to reopen D5.

## Caveats
- One repository, and both judges are models from one family (Codex).
- Only 580 of 8,685 functions were reached in the budget.
- Assertion recording covers node:test and Vitest only; pytest is not implemented.
